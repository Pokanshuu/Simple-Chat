# 32 · 个性化外观设计规范（壁纸 / 玻璃 / 字体 / 回收站 / 第三方声音）

> 起因：PR #9（`fa71424`）一次性加入了自定义字体、壁纸、玻璃表面、第三方声音 API 配置、回收站。
> 功能方向都对，但它和 §7.2、§15、§33 的既有规范有多处冲突，而且把"高度自定义"直接平铺给了所有用户。
> 本文先列出审查结论（§32.1），再给出**约束规范**（§32.2–32.4）和**逐功能的交互方案**（§32.5–32.9），
> 最后是落地清单（§32.10）。后续改外观相关的 UI，一律以本文为准。

---

## 32.0 一句话原则

> **默认就是 §7 那个干净的 SimpleChat；只有用户主动放了一张壁纸，界面才"为壁纸让路"。**
> 自定义是**逐层展开**的，每一层都有一个让人放心的默认值，以及一键回到上一层的出口。

由此推出三条硬规则：

| # | 规则 | 违反时的样子 |
|---|---|---|
| R1 | **未设置壁纸时，任何大面积表面都不得半透明，也不得掺主题色。** | 输入栏 / 抽屉 / 会话行透出底下的正文，整块界面发蓝（§7.2 已经否定过的"表面层染色"） |
| R2 | **玻璃效果 = 壁纸的附属品，不是独立开关。** 壁纸移除后，玻璃效果自动失效，参数保留但不生效。 | 关掉壁纸后玻璃效果还在，界面"坏了一半" |
| R3 | **正文可读性有硬下限，用户调不破。** 滑块的范围本身就是安全的，不靠用户自己把握分寸。 | 不透明度拉满、暗化为 0 → AI 回复直接压在照片上 |

### ✅ 应该保留的设计

- 回收站作为独立分组，与"重置"分开；软删除 + 无损恢复；跨对话记忆同步过滤 `deletedAt`。
- 字体分三层（界面 / 我的发言 / 模型回复），并且在 `PagedMessageBody` 的搜索、选择路径上也接了字体。
- 壁纸只画在聊天页，设置页保持纯色。
- 预览和聊天页共用 `drawWallpaper`（"预览即所得"）。
- 裁剪是独立入口，不在每次选图后强制弹出。
- 降采样近似模糊（零成本，兼容低版本）。

## 32.2 渐进式自定义：三层模型

"简洁"和"高度自定义"之间的矛盾，解法不是做减法，而是**分层**：

```
L0 默认      什么都不用做。§7 的干净界面。                         ← 90% 的用户停在这里
L1 一步到位   选一张图 / 选一款字体，其余全部自动给出合理值。          ← 想要个性化的用户
L2 精调      折叠在「更多调整」里的少量滑块，全部有安全范围。          ← 少数爱折腾的用户
```

每一层要遵守：

1. **下一层永远是折叠的**：L1 的页面上看不到 L2 的控件，只有一行「更多调整 ⌄」。
2. **每一层都能一键回退**：L2 有「恢复默认」，L1 有「移除壁纸 / 系统默认字体」。
3. **一个意图对应一个控件**："壁纸有多显眼"只用一个滑块表达，不拆成三个。
4. **自动优先于手动**：能从图片本身推算出来的（明暗、是否需要压暗），就不让用户调。
5. **范围即安全**：滑块的两端都必须是"可以用"的状态，不存在一个能把界面调坏的位置。

## 32.3 表面规则：什么时候透明，透明到什么程度

### 32.3.1 状态机

```
                 ┌──────────────── 无壁纸 ────────────────┐
                 │  glassAlpha = 0                         │
                 │  所有表面 = §7 实色                      │
                 │  不掺主题色                               │
                 └────────────┬────────────────────────────┘
                              │ 选择壁纸
                              ▼
                 ┌──────────────── 有壁纸 ────────────────┐
                 │  表面 = 实色 × SurfaceOpacity（按层取下限） │
                 │  正文区 = 保护层（见 32.4）               │
                 │  「玻璃表面」开关只在这里出现               │
                 └────────────┬────────────────────────────┘
                              │ 移除壁纸
                              ▼
                       回到无壁纸（参数保留，不生效）
```

实现上只在一个地方计算：

```kotlin
// ui/theme/Wallpaper.kt
val glassAlpha = if (wallpaperFile != null && glassEnabled) panelOpacity else 0f
```

其他组件**只读** `LocalSurfaceStyle`，自己不做任何判断。

### 32.3.2 表面 token（新增 `SurfaceOpacity`，与 `AppShadow` 同级）

把散落在 7 个文件里的下限收进一张表。用户调的是一个全局的「面板通透度」`t ∈ [0, 1]`，各层按下面的公式映射到自己的区间：

```
alpha(layer) = lerp(layer.solid, layer.floor, t)
```

| 层 | `floor`（最透） | `solid` | 理由 |
|---|---|---|---|
| 输入栏 / 输入面板 | 0.72 | 1.0 | 用户正在打字的地方；面板里还有列表和按钮 |
| 用户气泡 | 0.78 | 1.0 | 自己写的字，不能和背景糊在一起 |
| 抽屉 / 宽屏侧栏 | 0.80 | 1.0 | 盖在聊天内容之上，透多了就是两层字叠在一起 |
| 会话行（普通） | 0（不画底） | — | 行本身不画底，跟着抽屉走 |
| 会话行（当前 / 选中） | 跟随抽屉 + 选中色 | — | 靠选中色区分，不靠不透明度 |
| 菜单 / 对话框 / 分段控件 | **不透明** | 1.0 | 浮层和控件不参与玻璃效果 |
| 设置页 | **不透明** | 1.0 | 设置页没有壁纸，玻璃效果没有意义（删掉 `GlassCard`） |

要点：

- **下限比 PR #9 的高很多**（0.30–0.55 → 0.72–0.80）。没有真模糊（`RenderEffect` 要 API 31）的情况下，只靠半透明是"透明塑料"，不是"毛玻璃"。透明度越高，越需要背景本身已经被模糊。
- **API 31+ 才启用真模糊的毛玻璃**（`RenderEffect.createBlurEffect` 只模糊表面背后那块区域）；低版本退回"更实的半透明"（floor 再加 0.08）。规范层面只描述效果，不强求实现手段。
- **不掺主题色**。"白色玻璃在亮壁纸上太白"的正解是**从壁纸里自动取明暗**（见 §32.4），而不是把品牌色抹到表面上。主题色仍然只用于主色、选中态、用户气泡（§33.2）。
- **浮层不透明**：菜单、对话框、Toast 是"打断当前操作"的东西，必须一眼和背景分开。

### 32.3.3 悬浮控件的实时玻璃（R1 的唯一例外）

**范围**：只有**浮在正文之上**的控件——输入栏、输入面板（对话设置 / 思考档位 / 附件 / 生图参数）。抽屉、侧栏、会话行、气泡、菜单、对话框**不参与**。

**为什么允许在无壁纸时启用**：R1 禁止的是"大面积表面变透明或染色"。悬浮控件面积小，背后是正在滚动的正文，实时模糊能直接传达"这块浮在内容上面"，这是层级信息，不是装饰。默认值为 0（与现状完全一致），只有用户主动拖动滑块才会启用。

**一个滑块**：外观 › 悬浮控件 › 「玻璃质感」`g ∈ [0, 1]`，同时驱动混色和模糊，用户只需要表达"想要多通透"：

| g | 表面不透明度（混色） | 模糊半径 |
|---|---|---|
| 0 | 1.0（实色，等同关闭，不创建任何图层） | 0 |
| 0.5 | 0.79 | 12dp |
| 1 | 0.58 | 24dp |

- 混色 = 表面色 `card × alpha` 叠在模糊后的背景上，**不掺主题色**。
- 不透明度下限 0.58：输入栏里是用户正在输入的文字。模糊越强，背后越平，所以下限可以比 §32.3.2 的纯半透明下限更低。
- **降级**：Android 12 以下（没有 `RenderEffect`）只做混色，不做实时模糊；Android 12 及以上不因系统省电模式关闭已启用的亚克力。

**实现约束（性能）**：

1. g = 0 时**不创建**源图层，绘制路径与现在逐字节一致。
2. 源 = 消息区（页面底色 + 壁纸 + 消息列表）录制成的 `GraphicsLayer`，**只录制一次、绘制两次**：一次画在屏幕上，一次被悬浮控件引用。悬浮控件引用的是 RenderNode，**正文更新时不需要重新录制悬浮控件**。
3. 模糊只作用于控件自身那一小块区域（先裁切再模糊），面积远小于全屏。
4. 半径上限 24dp。模糊开销随半径和面积增长，再往上视觉收益很小，开销却明显变大。
5. 不对抽屉、侧栏这类整屏高度的面做实时模糊。

**必须在滑块下方用文字提示性能**（次级文字色）：

> 实时模糊会在每一帧重新计算背后的内容。流式输出、快速滚动时会增加 GPU 负载与耗电，低端机可能掉帧。Android 12 以下只保留半透明效果。

## 32.4 正文可读性：保护层（R3 的实现）

AI 回复没有气泡，是整个界面里最脆弱的一块。规则如下：

1. **壁纸永远画在保护层之下**：

   ```
   pageBackground（实色）
     → 壁纸（按用户参数调色、模糊）
     → 保护层：pageBackground × protection
     → 消息内容
   ```

2. `protection` **不由用户直接设置**，而是由"显眼度"滑块反推，并且有一个**由图片内容决定的下限**：
   - 解码时取一次缩略图的平均亮度 `L` 和亮度方差 `σ`（几十微秒）。
   - 浅色主题：底色是白色，图越暗、越花，保护层越厚；深色主题反过来。
   - 下限按"正文色 vs（壁纸 ⊕ 保护层）的最差对比度 ≥ 4.5:1"推算，先给出经验表，不需要逐像素计算：

   | 主题 \ 图片 | 亮且平 | 亮且花 | 暗且平 | 暗且花 |
   |---|---|---|---|---|
   | 浅色 | 0.45 | 0.60 | 0.70 | 0.80 |
   | 深色 | 0.75 | 0.82 | 0.50 | 0.62 |

3. 用户的"显眼度"滑块只能在 `[下限, 0.95]` 之间移动保护层。**把滑块拉到最显眼，也只是到达下限**，正文仍然可读。

4. 浅色 / 深色**各自记住一份**显眼度（C6）；跟随系统的用户切换主题时，不需要重新调整。

### 32.4.5 前景色：用透明度表达层级，不用灰色

**规则：凡是叠在表面上的前景（文字、图标、线条），层级一律用「正文色 × alpha」表达，不再写死一个灰色值。**

为什么：不透明的灰是"相对白底调出来的结果"，它的对比度只对那一种底色成立。
而 `onSurface × alpha` 是"在任何底上都取正文色的一部分"：底色变成灰色、变成照片，次级文字仍然会和正文一起变深或变浅，层级关系保持不变。
Material 的 `ContentAlpha` / `onSurfaceVariant` 也是同样的思路。

**新 token**（`ui/theme/Color.kt`，替代下表左列的写死值）。透明度按 §33.2 的做法**根据原色值反推**，保证在纯白 / 近黑底上视觉上不变：

| 语义 | 原值（浅 / 深） | 新值 | 用途 |
|---|---|---|---|
| `text.primary` | `#1A1A1A` / `#E8E8EA` | `onSurface` | 正文 |
| `text.secondary` | `#9AA0A6` / `#8B9099` | `onSurface × 0.56`（浅）/ `× 0.60`（深） | 说明文字、分组标签、行内 value、时间 |
| `text.process` | `#8A8F99` / `#9BA1AC` | `onSurface × 0.58` / `× 0.66` | 思考区文字 |
| `text.placeholder` | `#B8BCC4` / `#6B7079` | `onSurface × 0.38` / `× 0.42` | **仅限**输入框的占位符 |
| `line.divider` | `#F0F0F2` / `#26272A` | `onSurface × 0.06` / `× 0.08` | 分割线 |
| `line.outline` | `#EAEBEF` / `#2E2F33` | `onSurface × 0.09` / `× 0.12` | 描边 |
| `line.process` | `#D8DADE` / `#3A3D42` | `onSurface × 0.16` / `× 0.20` | 思考竖线 |

> 反推公式：`alpha = (bg − gray) / (bg − fg)`（按亮度分量计算）。上表数值偏保守，`secondary` 比纯数学反推值高约 0.1，顺便把原来偏淡的次级文字提到 4.5:1 附近。原灰色里那点冷色调会损失，这是可以接受的；如果坚持要保留，可以把 `onSurface` 换成"掺 4% 主色的 onSurface"，但不要退回不透明灰。

配套约束：

1. **`placeholder` 只能用在输入框占位符上。** 说明文字、hint、行内 value 统一用 `text.secondary`。PR #9 的 `FontSlotRow`、字体预览行、壁纸滑块的数值、回收站的"删除于…"都用错了。
2. **透明度是对比度的上限，不是保证。** 前景 alpha 只解决"层级关系不随底色变"，底本身的明暗仍然靠 §32.3 的表面下限和 §32.4 的保护层兜住。三者缺一不可：
   - 表面 / 保护层：保证底够干净；
   - 前景 alpha：保证层级跟着底色走；
   - 有壁纸时，次级文字的 alpha 自动 **+0.10**（`text.secondary` → 0.66），弥补底色不纯带来的对比度损失。
3. **背景类的"灰"也不能写死。** 代码块底、行内代码底、`fieldBackground`、选中态浅底，在有壁纸的表面上同样会消失。它们要么用 `onSurface × 低 alpha`（如代码块底 `× 0.05`），要么像选中态一样从主色派生（§33.2）。
4. **代码里禁止出现 `Color(0xFF8A8F99)` 这类灰色字面量**，也禁止 `Color.Gray`、`Color.White.copy(alpha = …)` 这种绕开 token 的写法（`WallpaperCropDialog` 里就有）。可以加一条 lint / grep 检查。

### 32.6.5 实际实现：全屏壁纸编辑器 + 通用裁剪器

**壁纸编辑器**（`ui/settings/WallpaperEditor.kt`），参照系统相册的编辑页：

```
┌ ✕            编辑壁纸            保存 ┐
│   最终效果全屏预览（屏幕比例）             │ ← 壁纸 + 聊天界面示意（气泡 / 回复 / 输入栏）
│   按真实屏幕比例缩小渲染                  │   字号、间距与真实页面成比例
├ [ 当前参数的滑块 ]             [对比] ┤ ← 按住「对比」看原图
├ [显眼度][暗化][模糊][亮度][对比度][饱和度]┤ ← 参数卡片：上面是数值，下面是名称
└      ( 裁切 )  ( 调节 )  ( 面板 )        ┘
```

- **选图后立即进入编辑器**，不再"先上传、再到设置页里调"。设置页只剩缩略图和「编辑壁纸 / 更换图片 / 移除壁纸」三个入口。
- **裁切**：画幅固定为屏幕比例，图片**始终铺满**，最小缩放 = 铺满所需的缩放；拖动、双指缩放、双击复位、水平翻转。裁剪结果直接写进文件，位置 / 缩放参数归位。**适配方式只剩"铺满"**：居中（露底）、完整显示（黑边）、拉伸（变形）三个选项全部删除。
- **调节**：所有参数共用一个滑块；亮度、对比度、饱和度在中点吸附，按相册习惯显示 −40…+40；模糊只有四档（无 / 轻 / 中 / 强），与聊天页的降采样档位一一对应，打开编辑器时预先算好四张降采样图，拖动时零解码。
- **面板**：透明玻璃面板开关、面板不透明度。
- **只在点「保存」时一次性落盘**，编辑过程中不写 DataStore。
- 原图单独保存一份（`wallpaper_source.jpg`，最长边 2560），「编辑壁纸」总是从原图重新开始，不会越裁越小。每次保存的结果使用带时间戳的文件名，聊天页据此重新解码。
- 参数区固定高度，切换分类时预览画幅不跳动。

**通用裁剪器**（`ui/common/ImageCropper.kt`）：

- 供待发送的图片附件使用：点缩略图进入看图页 → 顶栏「裁剪」。不在上传时强制弹出。
- 比例只提供好用的几档：原图比例 / 1:1 / 4:3 / 3:4 / 16:9 / 9:16。**没有自由比例、没有适配方式**，图片始终铺满裁剪框，不可能出现黑边或变形。
- 可选的 `preview` 插槽画在裁剪框内部，用于叠加"实际效果"示意。输出是原图像素坐标下的矩形，由调用方负责裁切和保存。
