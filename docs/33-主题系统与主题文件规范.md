# 33 · 主题系统与主题文件规范

> 目标：未来允许用户导入**主题文件**，对全部 UI 做美化和自定义。
> 本文定义分层架构、组件编码规范、主题文件 schema v1、安全兜底规则和存量代码的迁移计划。
> 与 [docs/32](32-个性化外观设计规范.md) 的关系：32 规定"界面应该长什么样、怎么交互"，33 规定"这些视觉取值从哪里来、怎么被替换"。

---

## 33.1 分层

```
┌────────────────────────────────────────────────────────────────┐
│ ④ 运行时兜底   ThemeResolver：对比度 ≥ 4.5:1、玻璃下限 ≥ 0.45、      │
│               模糊 ≤ 24dp、掺色 ≤ 0.12 —— 任何来源都改不破           │
├────────────────────────────────────────────────────────────────┤
│ ③ 用户设置     主题色、深浅模式、字号、字体槽、壁纸、玻璃、悬浮玻璃     │
│               （"我在这个主题里的偏好"，在 SettingsStore）             │
├────────────────────────────────────────────────────────────────┤
│ ② 主题文件     ThemeSpec（JSON / .sctheme 包），所有字段可选           │
│               （"这个主题长什么样"）                                  │
├────────────────────────────────────────────────────────────────┤
│ ① 内置默认值   ThemeTokens 各子结构的默认参数 + Color.kt + Theme.kt     │
└────────────────────────────────────────────────────────────────┘
                              ▼
                ThemeTokens ─▶ LocalThemeTokens ─▶ 组件
                         └──▶ LocalChatColors / MaterialTheme.colorScheme（兼容旧入口）
```

代码位置：

| 文件 | 职责 |
|---|---|
| `ui/theme/tokens/ThemeTokens.kt` | Token 结构（颜色、圆角、网格、阴影、表面）与 `AppTheme.tokens` 读取入口 |
| `ui/theme/tokens/ThemeSpec.kt` | 主题文件 schema v1 与 `ThemeFiles.parse / encode` |
| `ui/theme/tokens/ThemeResolver.kt` | 合并 ① ← ②，执行 ④ 的兜底；`ThemeSource` 接口与 `BuiltInThemeSource` |
| `ui/theme/Theme.kt` → `SimpleChatTheme(themeSpec = …)` | 唯一的装配点：构造 ①，叠加 ③ 的主题色，调用 Resolver，提供 CompositionLocal |
| `ui/theme/Glass.kt` → `glassSurface(base, GlassLayer)` | 壁纸玻璃的唯一实现，下限读 `SurfaceTokens` |
| `ui/theme/FloatingGlass.kt` | 悬浮控件实时玻璃，下限和模糊上限读 `SurfaceTokens` |
| `src/test/.../ThemeResolverTest.kt` | 合并、兜底、schema 兼容性的单元测试 |

## 33.2 组件编码规范（硬性）

1. **视觉取值只从 Token 读。** 颜色用 `LocalChatColors` / `MaterialTheme.colorScheme`（两者都来自同一份 Token），圆角、间距、阴影、玻璃下限用 `AppTheme.tokens.*`。
2. **禁止字面量**：`Color(0xFF…)`、`Color.Gray`、`RoundedCornerShape(数字.dp)`、玻璃相关的 `coerceAtLeast(0.xx)`。唯一允许出现颜色字面量的文件是 `Color.kt`。例外：固定深色语境的全屏媒体页（看图、裁剪器），它们与主题无关，常量写在文件底部并加注释说明。
3. **前景层级 = 正文色 × alpha**（docs/32 §32.4.5）。次级文字、占位符、线条、输入框底、代码块底都不能用不透明灰色。
4. **选中态 / 品牌浅底 = 主色 × alpha**，不要与页面底色混成实色。
5. **语义命名**：新 Token 按"它是什么"命名（`drawerFloor`、`bubbleTail`），不按"它在哪个文件"或"它是什么颜色"命名。
6. **新增一个可美化的属性**，需要同时做四件事：
   - 在 `ThemeTokens` 的子结构里加字段，默认值等于现在的视觉；
   - 在 `ThemeSpec` 对应位置加同名的**可选**字段；
   - 在 `ThemeResolver` 里合并它，并定义取值范围；
   - 在本文 §33.4 的表里登记。
7. **装配只在一处**：只有 `SimpleChatTheme` 可以构造 `ThemeTokens`，组件不要自己 `ThemeTokens(...)`。

检查命令（PR 前跑一遍；除注明的例外外应该没有结果）：

```bash
grep -rn "Color(0x" app/src/main/java --include=*.kt | grep -v "ui/theme/Color.kt"
```

```bash
grep -rn "coerceAtLeast(0\.[0-9]" app/src/main/java/com/simplechat/app/ui --include=*.kt
```

## 33.3 用户设置与主题文件的边界

| 归属 | 内容 | 原因 |
|---|---|---|
| 主题文件 ② | 配色、圆角、网格、玻璃下限、默认字体 / 默认壁纸 | 定义"一个主题"，可分享 |
| 用户设置 ③ | 深浅模式、主题色（主题文件没给 `primary` 时）、字号、三个字体槽、壁纸及其调节参数、玻璃开关、悬浮玻璃滑块 | 个人偏好，换主题时保留 |
| 不开放 | 布局结构、动效时长、交互逻辑、文案 | 改了就是另一个 App；也是可用性和无障碍的底线 |

冲突规则：**用户显式设置过的值优先于主题文件**。例如主题文件给了壁纸，但用户自己选过壁纸，就用用户的那张。主题文件里的字体和壁纸只作为"首次应用主题时的初始值"。

## 33.4 主题文件 schema v1

最小示例（只改主色）：

```json
{ "schema": 1, "light": { "colors": { "primary": "#FF6A00" } } }
```

完整结构（所有字段都可选）：

```json
{
  "schema": 1,
  "id": "com.example.sakura",
  "name": "Sakura",
  "author": "someone",
  "version": "1.0.0",

  "light": { "colors": {
    "primary": "#E05A8A", "onPrimary": "#FFFFFF",
    "pageBackground": "#FFFBFC", "settingsBackground": "#FBF3F6",
    "card": "#FFFFFF", "menuBackground": "#FFFFFF",
    "text": "#2A1B21",
    "userBubble": "#FBE1EA", "onUserBubble": "#2A1B21",
    "danger": "#E5484D", "warning": "#D98A1F",
    "codeBlock": "#0000000A", "inlineCode": "#00000014", "quoteBar": "#00000057"
  }},
  "dark": { "colors": { "…": "同上" } },

  "shapes":  { "soft": 14, "menu": 18, "container": 24, "bubble": 18, "bubbleTail": 6 },
  "space":   { "screen": 16, "inline": 12, "gap": 8, "section": 24 },
  "surface": {
    "drawerFloor": 0.80, "userBubbleFloor": 0.78, "rowFloor": 0.55,
    "floatingFloorBlurred": 0.58, "floatingFloorPlain": 0.86,
    "floatingMaxBlur": 24, "accentTint": 0
  },

  "fonts":     { "ui": "fonts/ui.ttf", "user": "fonts/hand.ttf", "assistant": "fonts/serif.otf" },
  "wallpaper": { "image": "wallpaper/light.jpg", "imageDark": "wallpaper/dark.jpg",
                 "opacity": 0.35, "blur": 1, "dim": 0, "glass": true }
}
```

字段表：

| 路径 | 类型 / 单位 | 取值范围（越界钳回） | 说明 |
|---|---|---|---|
| `schema` | int | 1..当前版本 | 比当前版本新时**拒绝加载** |
| `light/dark.colors.*` | `#RRGGBB` / `#AARRGGBB` | — | 解析失败的单项忽略 |
| `colors.text` | 颜色 | 与 `pageBackground`、`card` 的对比度都要 ≥ 4.5:1 | 不满足时 text/pageBackground/card **整组退回默认**；次级文字、占位符、线条全部从它派生，主题文件不单独提供 |
| `shapes.*` | dp | soft 0–28 · menu 0–32 · container 0–36 · bubble 0–28 | 只能改四档的数值，不能新增档位 |
| `space.*` | dp | screen 8–32 · inline 4–24 · gap 2–16 · section 8–48 | |
| `surface.*Floor` | 0..1 | ≥ 0.45（`SafetyFloor`） | 可读性红线 |
| `surface.floatingMaxBlur` | dp | ≤ 24 | 性能红线 |
| `surface.accentTint` | 0..1 | ≤ 0.12 | 默认 0，表面不染色 |
| `fonts.*` / `wallpaper.*` | 包内相对路径 | — | **v1 只解析不加载**，等 §33.6 的包格式落地后启用 |

兼容性约定：

- **未知字段忽略**：新版本主题文件放进老 App 不会崩，多出来的字段只是不生效。
- **字段只增不改**：已发布的字段永远不改名、不改语义；确实需要改时提升 `schema`，并在 Resolver 里保留旧版本的映射。
- 字段缺失 = 用下一层的值。这一点由 `ThemeResolverTest` 保证。

## 33.5 安全兜底（第 ④ 层）

主题文件来自第三方，**任何主题都不能把界面弄到不可读或卡顿**。Resolver 在合并时执行：

| 规则 | 动作 | 记录 |
|---|---|---|
| 正文对比度 < 4.5:1 | 正文、页面底、卡片整组回退 | `warnings` |
| 玻璃下限 < 0.45 | 钳到 0.45 | `warnings` |
| 模糊 > 24dp | 钳到 24dp | — |
| 掺色 > 0.12 | 钳到 0.12 | — |
| 尺寸越界 | 钳到范围内 | — |

`ResolvedTheme.warnings` 用于导入时提示用户："这个主题的以下设置因可读性被调整"。

## 33.6 预留：主题包与导入流程（未实现）

- **格式**：`.sctheme` = zip，内容为 `theme.json` + `fonts/` + `wallpaper/` + `preview.png`。
- **导入**：设置 › 外观 › 主题 › 导入 → 解析 → 展示预览和 `warnings` → 应用。资源解压到 `filesDir/themes/<id>/`。
- **接入点**：实现 `ThemeSource`（例如 `FileThemeSource(context, id)`，`observe()` 返回解析后的 `ThemeSpec`），在 `MainActivity` 里 `collectAsState` 后传给 `SimpleChatTheme(themeSpec = …)`。**上层组件不需要任何改动**。
- **导出**：`ThemeFiles.encode(spec)` 加上当前用户设置里可分享的部分，打包成 `.sctheme`。
- **安全**：只读包内的 JSON 和图片 / 字体字节，不执行任何代码；字体沿用 `FontFiles` 的魔数校验；图片沿用 `WallpaperFiles` 的尺寸上限。

## 33.7 存量代码迁移计划

这一轮已经完成：

- [x] Token 结构、schema、Resolver、单元测试；`SimpleChatTheme` 统一装配，`LocalChatColors` 和 `colorScheme` 都来自 Token（所以主题文件里的颜色**现在就对全应用生效**）。
- [x] 前景色和填充色全部改为"正文色 / 主色 × alpha"：次级文字、过程文字、占位符、分割线、描边、思考竖线、输入框底、代码块底、行内代码底、引用竖线、选中态浅底。
- [x] 壁纸玻璃 7 处散落的下限 → `glassSurface(base, GlassLayer)` + `SurfaceTokens`；不再掺主题色。
- [x] 悬浮玻璃的下限和模糊上限 → `SurfaceTokens`。

待迁移（按收益排序，每项都可以单独提交）：

| # | 存量入口 | 目标 | 规模 |
|---|---|---|---|
