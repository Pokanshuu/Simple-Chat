# Simple Chat 生图 · Sol 实施任务书

请在当前 Android/Kotlin 仓库实现下面的功能。交付包括设置、聊天入口、真实请求适配器、消息持久化和回归验证。本文基于 main 的 a8760bb。交接文档中的旧分支、账号、脚本和机器路径仅作历史背景，开发从当前检出版本开始。

## 1. 用户第一次生成一张图

1. 聊天页点「＋ → 生成图片」。复用附件面板的图标、间距和触摸反馈，图标用画框或图片加号，与「选择图片」区分。无可用模型时入口仍可点，说明原因并提供「配置生图 API」和「选择聊天模型」。从设置返回时保留当前会话和草稿。
2. 打开底部面板，标题「生成图片」。第一行只读显示「当前聊天模型 · 模型名」或「独立 API · 模型名」。多行输入框标签「画面描述」，示例「傍晚的香港街口，雨刚停，霓虹倒映在路面」。默认聚焦。普通聊天输入已有文字时可复制进来，退出或提交生图均保留原聊天草稿。生图草稿按会话单独保存，成功提交后清空。
3. 输入下方放一行「画幅」单选项，默认「自动」。仅列出当前适配器和模型能表达的比例，实际尺寸可在选项旁或下方查看。只支持默认值时隐藏选择器。首版每次请求一张。高级参数等有适配器需求再加。
4. 底部主按钮「生成图片」。纯空白禁用。按钮与键盘避让，窄屏或大字体允许选项换行。点一次即锁住本次提交，落库成功才收面板。写库失败保留表单和提示词。
5. 用户侧生成一条提示词，助手侧紧跟一张与输出比例一致的占位卡。无明确比例时用 1:1。图片解码可显示后在原位置替换占位，点击打开现有大图查看器。生成结果属于发起时的会话和用户消息分支。

## 2. 设置与路由

入口放在「设置 → API → 独立工具 API」，和搜索、文件并列。列表项为「生图 API」，副标题取「独立 · 模型名」「使用聊天模型 · 模型名」或「尚未配置可用模型」。配置按活动 API 档案隔离。

- 页面开关「使用独立生图 API」。关闭时显示当前聊天模型及它能否出图，并保留已保存的独立设置。能力未知时给出模型能力设置入口。
- 打开后依次显示「协议」「连接」「生图模型」「默认画幅」。连接默认「使用当前聊天连接」，动态引用本档案的地址与密钥，可单独指定生图模型。选择「自定义连接」后填写独立 Base URL 和密钥，显示实际目的主机。自定义主机默认使用独立密钥。若提供跨主机复用聊天密钥选项，要让用户主动选择并看到目的主机。密钥按现有方式加密、遮盖、留空保留。
- 模型 ID 可手填，拉取模型列表只作辅助。保存时按当前协议校验地址、模型和尺寸。沿用工具表单现有的返回保存、错误定位及档案 ID 校验。把「试生成」和保存分开，点试生成时明确将提交一次可能收费的请求，可沿用聊天页的提示词表单，结果留在测试页。

| 独立 API | 当前条件 | 点生成后的行为 |
|---|---|---|
| 开 | 配置有效 | 只请求所选独立适配器，即使当前聊天模型仅支持文本也能出图 |
| 开 | 配置缺失或请求失败 | 显示对应字段或请求错误，提供修改或手动重试 |
| 关 | 聊天协议和模型支持图像输出 | 使用本次会话实际选中的模型、当前档案连接及所需请求头，走聊天协议 |
| 关 | 能力未知、仅识图或尚无协议适配 | 提示「当前模型尚未配置图像输出」，提供设置与切换模型入口，发送请求数为零 |

能力按「用户对该档案与模型的覆盖 → 端点返回的输出能力 → 已验证的适配规则 → 未知」解析。输入图像、输出图像、Responses 托管生图工具要分别表达。独立路径只校验实际用到的连接和模型。服务端拒绝时保留错误来源，切换后端或重新计费须由用户发起。普通文字聊天沿用当前行为；独立生图 API 启用时，会向当前聊天协议注册 `generate_image` 工具，模型只在识别到明确的作图意图时触发该工具。只有配置了生图 API 才开放此工具，不提供空壳工具。

## 3. 助手卡片与点阵动效

两张参考图中，浅色靠细灰点形成纹理，深色靠低亮度灰点从暗底浮出。保留固定、整齐的点位，让一小片区域逐渐变大变亮，隔壁点晚半拍跟上。底色、文字和按钮全程稳定。

| 项 | 首版规格 |
|---|---|
| 卡片 | 左对齐，跟助手附件同一列。建议宽 240–280 dp，窄屏取可用宽度，横竖比例沿用请求，超长边按现有附件上限收敛。使用现有附件圆角。状态操作行放在点阵下方，避免盖住图片 |
| 布点 | 正交网格，中心距 8 dp，水平垂直居中，半径 0.55–1.45 dp。靠近四边的点轻微变淡，点位始终固定 |
| 节奏 | 周期 2.8 秒，波峰从左上往右下走。相邻点连续错相，每个点平滑地小→大→小。峰值只占局部区域，全屏没有明暗闪切 |
| 浅／深 | 取本主题的 surface 和 onSurface。浅色点透明度从约 10% 到 38%，深色约 12% 到 46%。透明度随半径变化。避免把主题强调色铺满卡片 |
| 状态行 | 左侧「正在生成图片」，右侧「停止」。若能区分真实下载阶段才显示「正在接收图片」。服务器未报告进度时只展示不定进度。超过 30 秒可显示「仍在等待模型返回」 |
| 完成 | 缩略图就绪后在同一卡片交叉淡入约 180 ms。保持消息锚点。比例与预期不同时先在原框完整适配，大图使用真实比例 |
| 无障碍 | 系统减少动态效果或动画倍率为零时显示静态点阵。TalkBack 合并为一个状态节点，只播报状态变更。停止、重试和预览的触摸目标至少 48 dp |

Compose 实现建议用一个 Canvas 和一个动画相位，只在 draw 阶段读取相位。缓存网格坐标和空间相位，不给每个圆点创建 Composable 或动画对象。离屏、页面非前台、请求终止时停止绘制循环。下面的公式可以直接复现节奏，u、v 为卡片内 0 到 1 的归一化坐标。

```text
t = (elapsedMs % 2800) / 2800
wave = (0.5 + 0.5 * cos(2π * (t - 0.85*u - 0.55*v)))²
radiusDp = 0.55 + 0.90 * wave
alpha = lerp(themeMinAlpha, themeMaxAlpha, wave) * edgeFade
```

## 4. 一条消息从提交到结束

| 状态 | 界面与操作 | 数据约束 |
|---|---|---|
| 提交中 | 主按钮禁用，保留输入 | 建立用户提示词与助手占位的父子关系，只接受一次提交 |
| 等待／接收 | 显示点阵与停止按钮，允许滚动 | 保存档案 ID、模型、协议、画幅、消息 ID、尝试标识。独立端点默认只收到用户确认的画面描述与参数 |
| 完成 | 显示可点开的大图缩略图，可通过消息菜单「再生成一张」 | 完整图片校验并落盘后，事务提交附件引用和 DONE，记录实际 MIME 与宽高 |
| 用户停止 | 原位显示「已停止」与「重新生成」 | 取消网络与下载、清理半成品，写 STOPPED。晚到结果按尝试标识丢弃。仅可保证客户端停止接收 |
| 失败 | 原位短原因，提供「重试」或「修改配置」 | 写 ERROR。区分鉴权、超额/限流、超时、服务拒绝、响应无图、下载/存储失败。服务端有文字说明时显示适量文本 |
| 重试／再生成 | 保留原提示词，在该条下新增助手版本，使用现有分支切换 | 走生图入口，显式重提一次。原配置或模型已更换则在提交前展示将使用的当前路由 |

首版沿用当前聊天切换会话即停止的语义，切换前提示「切换会话将停止本次生成」。确认切换后旧消息留在原会话并标记已停止。旋转屏幕重绑定同一任务，应用进程重启则回收悬挂任务并提示可重试。滚动离屏只暂停绘制。数据库终态用条件更新防止停止和最后一帧竞态。只有用户主动请求才触发新的付费 POST。

## 5. 协议与结果落盘

实现一个共用请求协调器和按协议选择的适配器。输入包含已解析路由、提示词和模型支持的选项，输出包含可选文字与已验证的本地图像引用。首版接通下列独立与聊天路径，各自准备脱敏请求和响应 fixture。

| 路径 | 请求与结果约定 |
|---|---|
| 独立 · OpenAI Images 兼容 | `POST /images/generations`，使用 `model`、`prompt` 和该模型支持的尺寸。解析 `data[].b64_json`，对明确返回 `data[].url` 的兼容端点走受限下载。地址拼接保留用户的版本根路径 |
| 独立 · DashScope 多模态同步 | 依千问对应模型文档构建 `input.messages[].content[].text`，按支持情况用 `parameters.size` 表达 `宽*高`，解析 `output.choices[].message.content[].image` 的临时 URL 或 Data URL。异步任务型模型需要独立的提交和轮询适配，列表上标清支持范围 |
| 聊天 · Responses 生图工具 | 沿用当前聊天模型和 Responses 端点，用户点生图时声明 `image_generation` 工具。在支持的路由上明确选择该工具。取最终 `image_generation_call.result`，中间预览不入库。仅返回文字或拒绝时显示对应说明 |
| 聊天 · 兼容多模态输出 | 为有明确协议样例的网关实现 Chat Completions 路径，用它要求的输出模态发起请求，解析其声明的结构化图片字段。以实际 fixture 验证 `message.images` 或 content 图像块，每种方言独立声明支持范围。普通正文里的网址仍按正文显示 |

生图入口可用非流式请求起步，聊天文字的 SSE 正常工作。模型能力目录需要同时匹配协议与模型。原生聊天请求复用已有消息构造与档案头，保留当前活动分支的文本上下文。独立连接默认只发送面板中的提示词。生成图片作为助手附件保存在本地，回放历史时沿用角色和协议的图像限制，避免给只收文本的模型发送附件或 Base64 文本。

下载图片用独立的无凭证请求，逐跳校验 HTTPS URL，拒绝本地和内网地址，限制重定向次数、时间、字节数与解码像素。Base64 与网络 JSON 同样需要大小上限，避免重复物化大字符串。先写临时文件，校验为支持的位图格式后再提交。失败、取消、数据库更新失效均回收临时文件。诊断只记录协议、状态、耗时和大小，密钥、签名 URL、Base64 和提示词留在日志之外。

## 6. 代码落点与交付顺序

| 顺序 | 在代码中定位 | 完成标志 |
|---|---|---|
| 1 | `ApiProfile`、`StoredSettings`、`SettingsStore` 的 snapshot/activate、`RemoteModelMetadata`、`ModelCapabilityOverride` | 新增按档案保存的生图配置及图像输出能力覆盖，旧配置缺字段正常加载。纯函数解析四种路由，可单测 |
| 2 | `SettingsScreen` 的 API_PROFILES 子页、`ToolApisPage`、`ServiceApiPage` | 工具组可进入编辑，地址和密钥继承、切换档案、校验和返回行为实测通过 |
| 3 | `AttachmentPanelContent`、`ChatScreen`、`MessageList`、`MessageAttachments` | 先用本地 fixture 跑通草稿→点阵→成图／停止／失败，在浅深主题、字体放大和禁用动画下验收 |
| 4 | `ChatViewModel`、`ChatRepository`、`AttachmentFiles`、`GenerationService` 的任务所有权 | 复用发送锁、分支模型、停止与恢复。持久化生图标识和重试所需非敏感参数。若新增 Room 字段，提供 migration 和默认值，并检查导入导出兼容 |
| 5 | `net` 的请求取消、`ChatApi`、`ResponsesApi`，新增独立生图适配器 | 两类独立接口和聊天回退分别接通。仅当 fixture 或联调可验证时在能力列表中标为可用 |

## 7. 验收清单

- [ ] 纯文字聊天模型 + 独立生图服务可生成一张图。复用聊天连接时生图模型可另选。自定义连接时仅访问用户所选主机。开关关闭后立即恢复聊天路由。
- [ ] 关闭独立 API，支持图像输出的聊天模型可出图；仅支持识图的模型显示配置入口。普通聊天继续输出文字。开关开启但配置错误时只发一次请求。
- [ ] 对每个列为支持的协议，验证请求路径、鉴权、提示词、画幅与结果字段。覆盖 URL、Base64、文字和图片混排、仅文字、损坏图片、超限和超时响应。
- [ ] 连点生成只产生一次任务。旋转、离屏再回来保持请求身份。停止与接收同时发生时只有一个终态。切会话或删除分支后，迟到的图片不会挂到新会话。
- [ ] 生图失败可改配置再试。重试仍生成图片；成功图、失败记录和助手版本可在重开会话时正确读取。备份再导入的成功图可打开。
- [ ] 浅色与深色对照参考图。波峰局部移动、点位固定，卡片外文字稳定。大字号不遮挡停止按钮，关闭系统动画时呈静态，读屏只报告状态变化。
- [ ] 新增字符串覆盖项目已有语言资源。运行 `gradlew.bat :app:testDebugUnitTest :app:assembleDebug`，记录 fixture 测试、模拟器验收和真实端点联调各自的结果。真实请求使用开发者自行配置的凭证。

协议核对可查 OpenAI API 的 Create image 与 Image generation tool，以及阿里云百炼的《千问-图像生成与编辑 API参考》。协议支持以实现配套的响应样本为准。

## 8. 官方模型核对（2026-11-21）

- Google Gemini 的生图入口提示 `gemini-nano-banana-2.1`。官方新模型使用 `/v1beta/interactions`，兼容网关仍可使用 `generateContent`。参考 [Google 生图指南](https://ai.google.dev/gemini-api/docs/image-generation)。
- OpenAI 独立 Images API 可填写 `gpt-image-2.6-sunburst` 或 `gpt-image-2.6-flare`。官方 Responses 路径使用 API 参考列出的默认生图模型 `gpt-image-2.6-sunburst`。兼容网关使用其配置的默认生图模型。参考 [OpenAI Responses API 参考](https://developers.openai.com/api/reference/resources/responses/methods/create)。
- DeepSeek 等聊天服务声明 `generate_image` 函数。收到完整工具调用后，应用发出一次生图请求并将结果挂到当前助手消息。实际触发取决于聊天端点能否返回该协议的工具调用。
- 已运行 Android 单元测试和 Debug 构建，并在模拟器验证生图入口与配置页跳转。第三方服务的实际出图仍待凭证联调。
