## 1. 项目概述

### 1.1 目标与使用场景

做一个**轻量、简洁、原生性能**的 Android 端 AI 对话客户端。视觉与交互对标 DeepSeek 客户端的克制风格，但不依赖 DeepSeek 的账号体系，支持自填 API Key 接入任意 OpenAI 兼容服务。

**主要用途：长文本连续创作（续写 / 设定推演）**

这个用途决定了几条硬性设计要求：

| 场景特征 | 对应设计 |
|---|---|
| **长文本输出**（单章数千字） | 流式渲染性能是核心指标，不能因渲染卡顿打断创作心流 |
| **多轮连续创作**，上下文极长 | 必须有**上下文占用可视化**与**手动裁剪**能力 |
| **角色/文风需要稳定** | 必须有**全局预设（角色卡）**：System Prompt + 参数打包切换 |
| **需要挑选不同剧情走向** | **多版本分支 `‹ n/m ›`** 不是锦上添花，而是核心功能 |
| **需要反复修改 AI 生成的内容** | 任意位置编辑 AI 消息 |
| **原有工具卡顿/受服务端限制** | 接任意 OpenAI 兼容端点（含自建/本地），**客户端不改写内容** |
| **数据敏感** | 完全本地存储，不联网同步；API Key 用 Keystore 加密 |

**项目动因**：Chatbox 的 WebView 渲染在长文本场景下明显卡顿；官方客户端会屏蔽创作内容。
因此本项目的第一要义是 **轻量流畅**，其次是 **原样转发、可自定义**。

### 1.2 设计原则

> **轻量流畅是第一要义。** 任何功能在"更好用"与"更流畅"之间冲突时，优先保流畅。

| 原则 | 具体含义 |
|---|---|
| **流畅优先** | 所有渲染与存储策略围绕「长文本流式不卡」设计（见 §8） |
| **轻量优先** | 依赖精简，不做账号/云同步/社交/广告/插件。APK 目标：release ≤ 12 MB |
| **原生性能** | 单 Activity、无 Navigation 库、无 DI 框架、无反射 |
| **视觉克制** | 无多余装饰。白底、大间距、少分隔线、少阴影，把屏幕留给正文 |
| **不改写内容** | 客户端不做替换或拦截，请求原样送达所配服务端 |
| **可控可测** | 每个里程碑都能编译并跑出可见效果，不做"憋大招"式开发 |

### 1.3 明确不做（Non-Goals）

- 账号体系、云同步、多设备
- 社交分享、社区、插件系统
- 广告、埋点统计
- **任何形式的客户端改写或拦截**
- 工具调用（Function Calling）执行链 —— **数据结构预留，本期不实现**
- 数学公式渲染 —— 用户确认用不到，本期不做（扩展方案见 §11.4）

### 1.4 与 Chatbox 的关系：数据可迁移

用户此前使用 Chatbox，需要把已有创作迁移过来。因此本项目提供
**Chatbox 数据导入**（见 §11.7），并在数据结构上刻意与 Chatbox 对齐：

| Chatbox 概念 | 本项目对应 |
|---|---|
| `Session` | `conversations` |
| `Message { role, content, contentParts }` | `messages` |
| `MessageReasoningPart` | `messages.reasoning` |
| `MessageImagePart` | `attachments` |
| **`messageForksHash`（备选回复分支）** | **`messages` 的槽位 + `variantIndex`** |
| `MessageRoleEnum: system/user/assistant/tool` | `messages.role` |

> Chatbox 自身就用 `messageForksHash` + `ForkService` 来组织备选回复分支
> （其 release notes：「Organized alternative replies into collapsible branches」）。
> 这从侧面验证了本项目选择的「槽位 + 多版本」模型（§4.1）与用户既有心智一致。

## 9. 需求清单

### 9.1 功能分级

| 级别 | 内容 |
|---|---|
| **P0 核心** | 流式对话 · 停止生成 · 深度思考折叠 · 完整 Markdown · 历史抽屉 · 搜索对话 · 置顶/重命名/多选/删除 · 复制/重新生成/编辑/删除单条 · 设置页 · 空态 · 回到底部 · 自动生成会话标题 · 主题三模式 · 双 Provider |
| **P1 增强** | 导出对话(md/json) · **全局预设/角色卡** · 高级参数 · 代码块复制 + 超长折叠 · 性能仪表(ttft/tps) + **上下文占用与裁剪** · **重新生成与编辑的多版本分支 `‹ n/m ›`** · API Key Keystore 加密 · 图片多模态输入 · **Chatbox 数据导入** |
| **P2 未做** | 工具调用 · 数学公式 · 语音输入 · TTS 朗读 · 云同步 · MCP |

### 9.1.1 创作向专项功能

以下四项由「长文本创作」这一主用途直接推导，是本项目相对 DeepSeek 客户端的主要增量。

> **设计取向**：**不做复杂化，保泛用性**。所有"角色卡/世界书/人格"之类概念的底层
> 本质都是**一段系统提示词**。因此本项目统一抽象为「预设」——一个可命名的
> 系统提示词片段，不做专有结构化字段，也不兼容外部角色卡格式。

**① 预设（系统提示词片段）**

```
预设库（全局，跨会话复用）
  ├─ 默认助手          （空）
  ├─ 第三人称叙事       （"保持第三人称限制视角，克制心理描写…"）
  ├─ 角色：A          （一段人物设定文字）
  └─ 角色：B          （一段人物设定文字）

会话挂载：可多选、可排序、可单独启停
最终系统提示词 = 会话补充提示词 + 各启用预设按序拼接
```

- **一个会话可挂多个预设**：扮演场景下每个预设就是一个角色
- **会话另有独立的补充提示词**，用于本会话特有的设定
- 必须是**纯文本、可自由编辑**，不做表单化的专有字段
- **提供「系统提示词预览」**：可折叠地展示实际发送的完整文本，
  避免"预设没生效/拼接顺序不对"的黑盒问题
- 管理入口：设置页的「预设」分组；会话内可从顶栏快速切换

**② 两种会话模式**

| 模式 | 定位 | 系统提示词默认模板 |
|---|---|---|
| **创作模式** | AI 是写作助手，产出正文 | 引导：直接输出正文，不解释、不寒暄，保持人称与文风统一 |
| **扮演模式** | AI 扮演角色，对话推进 | 引导：同时扮演以下角色，以对话与动作描写推进剧情 |

- 模式在**空态中央**用**可拖动的分段控件**切换（见 §7.3 ①）
- 模式影响：内置引导模板、空态文案、输入区提示
- 模式可在会话中切换（影响后续请求的构造，历史消息不变）

**③ 上下文占用与压缩（Compact）**

长篇创作会把上下文迅速撑大。1M 窗口虽大，但成本随长度线性上升。

> **核心前提**：**压缩只改变发给 API 的内容，绝不删除本地消息。**
> 界面永远显示完整历史。这既省 token 又不丢创作素材。

- **本地 token 估算**（不调 API）：中文约 1 token ≈ 1.5 字符、英文约 1 token ≈ 4 字符
  加权估算。误差可接受，仅用于可视化与阈值判断
- 顶栏显示**上下文占用进度条**，接近阈值时变色
- **触发策略：手动为主 + 阈值提醒**。达到阈值时提示「建议压缩」，
  由用户决定，不在创作中途悄悄改变上下文
- **摘要可查看 / 可编辑 / 可重新生成**。AI 记错人名地名时用户能直接修正，
  避免错误在后续压缩中累积放大
- **摘要提示词模板可自定义**（全局设置项，给一份适合文学创作的默认模板）。
  模板化而非硬编码 —— 保持泛用性
- **增量滚动压缩**：新摘要 = 旧摘要 + 新增内容 → 重新生成，
  而不是每次全文重摘。摘要更稳定、成本更低
- **保留最近 N 条原文不压缩**：保证续写的即时语气连贯

数据模型：

```sql
compactions(
  id, conversationId,
  fromSlotIndex, toSlotIndex,   -- 覆盖的消息范围
  summary,                      -- 摘要正文（可编辑）
  createdAt, updatedAt
)
```

请求装配时，摘要以「前情提要」形式紧跟系统提示词之后：

```
[system]  会话补充提示词 + 预设拼接 + "以下是前情提要：<摘要>"
[user/assistant]  最近 N 条未压缩原文
[user]  本轮输入
```

**④ 不改写内容**

不对 prompt 与 response 做任何关键词匹配、拦截、改写、上报。
Provider 层不插入任何指令（除用户自己配置的预设与会话补充提示词）。

### 9.2 消息操作

- **复制**：复制消息文本
- **重新生成**：为该 slot 生成新版本，`‹ n/m ›` 切换
- **编辑**：任意位置（user 与 assistant 均可）
  - 编辑 AI 消息 → 该 slot 新增版本，后续不变
  - 编辑用户消息 → 提供「编辑」（仅改文字）与「编辑并重发」（改完重新生成后续）两项
- **删除单条**：删除该消息
- **标记为不发送**：保留显示但排除出上下文（见 §9.1.1②）
- **会话管理**：重命名 / 置顶 / 多选 / 删除 / 搜索

> ⚠️ **后续撤下项**：「标记为不发送」已撤下（DB 列休眠，见 §17.6）；
> 「创作 / 扮演」模式切换已隐藏为远期功能（见 §17.7）。
> 本节的「重新生成为该 slot 新增版本」在当时是槽位模型，v1.8 起已改为 **parentId 树**
> （见 §4.1 / §18）。
