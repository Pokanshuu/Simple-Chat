# LaTeX 排版与渲染施工方案（2026-11-20）

## 1. 目标与边界

系统完善聊天消息中的 LaTeX 排版、兼容性、主题、流式更新、选择与导出。本轮先固定诊断和验收标准，再据此实施；不改消息存储格式和 API 数据格式。

覆盖行内/行间公式、Markdown 容器（引用、列表、表格）、不支持语法 fallback、消息流式/定稿、选择复制、图片分享和 Markdown 导出。

## 2. 现状盘点

- Markdown 主体由 `multiplatform-markdown-renderer` 渲染。
- 数学公式采用 `latex-renderer` 1.7.3 的 Compose 原生渲染，不使用 WebView。
- `MathSplit.kt` 识别 `$…$`、`$$…$$`、`\(…\)`、`\[…\]`，并跳过代码。
- `InlineMath.kt` 将行内公式编码为 Markdown token，再以 annotator 和 `InlineTextContent` 放回原段落。
- `MarkdownWithMath.kt` 负责显式行间公式分块；行内公式应继续留在原段落。
- `LatexCompatibility.kt` 处理部分布局包装、中文文本、椭圆框和源文本 fallback。
- 已有解析、兼容性与 token 生成测试；仍需验证 Compose 实际测量、基线、裁切、窄屏行为、流式、主题和导出的一致性。

### 关于附件截图

附件呈现的公式打断正文换行，是 v1.1.4 时期已修复的历史问题，不作为当前缺陷结论，也不据此要求重写。将其保留为防回归样例：确认行内公式仍与前后正文连续排版；若现版已通过，只记录回归通过，不重复修旧问题。

### 当前需要审计的风险

1. native、兼容包装、Oval 分段和源文本 fallback 分属不同渲染分支，可能在基线、字号、间距、选择行为上不一致。
2. InlineTextContent 的宽、高、baseline 和缩放边界需要以实际布局验证，重点检查窄屏及复杂上下标/分式是否裁切或异常撑高。
3. 复杂 LaTeX 命令的支持边界与中文文本表现须建立样例表；未知语法必须完整 fallback，不能静默丢内容。
4. 屏幕、分享图片和 Markdown 导出有不同绘制路径；一处通过不能代表其他路径通过。
5. 设计文档仍含“公式未实现”的过时说明，实施后需同步清理。

## 3. 架构决策

### 首选方案：保留现有分层，按证据完善

现有实现已经包含 Markdown parser、Compose 原生公式 renderer、兼容层、导出支持和测试。当前没有证据证明架构基础不可用。先做基线和覆盖率审计，优先修复可定位的适配、测量、基线、fallback 或导出问题，不重写完整排版引擎。

实施约束：

- Markdown 结构由现有解析器处理；行内公式必须作为 inline content 参与自然折行。
- 仅独占行的 `$$…$$` 和 `\[…\]` 作为 display math 块。
- 代码、转义标记、金额和未闭合定界符不得误识别为公式。
- 不支持或畸形公式完整保留源文本及相邻内容；不得删除未知命令或参数。
- 主题颜色跟随应用强制主题，公式背景透明；上下标、分式和根式不得被裁切。
- 短行内公式不应制造横向滚动；长公式应有可预测的查看策略，不能静默截断。

### 替换架构的决策门

只有在确认缺陷来自现有 renderer 本身、无法由输入规范化/适配层/Compose 测量修复后，才比较替代方案。候选需以最小原型覆盖：CJK 与基线、自然折行、复杂公式、字体缩放、选择复制、主题、长列表滚动、离线能力、导出、包体、许可和维护成本。

如评估 KaTeX/WebView，禁止每个公式各建一个 WebView；须验证宿主复用、生命周期、滚动同步、文本选择、无障碍与导出。除非对照验证证明收益，保持 Compose 原生方案。从零手写完整 TeX 排版器不作为默认路线；少数命令缺失优先增加有界且单测覆盖的兼容适配。

## 4. 施工步骤

### 阶段 A：建立基线

1. 用附件对应语句构造防回归输入，标明其来源为历史截图近似样例。
2. 覆盖实际保存的原始 Markdown；逐段记录 `splitMath()`、`inlineMathDocument()`、Markdown AST、inline map 和最终布局结果，必要时取得真实消息源文本。
3. 记录设备宽度、系统字号、应用主题、是否流式、消息容器及导出类型。
4. 同一组样例跑聊天气泡、分享长图/分页图、Markdown 导出，建立截图基线。

### 阶段 B：补齐排版与兼容

1. 完善解析契约测试：代码/转义/金额/未闭合/相邻公式、标点、强调、链接、引用、列表、表格。
2. 校准行内 placeholder 的自然尺寸、baseline、窄屏降级和 Compose 尺寸上限，避免吞内容或产生意外段落。
3. 统一 native、兼容包装、Oval 和 fallback 的视觉间距、正文色、选择/复制行为。
4. 建立命令兼容矩阵：分式、根式、上下标、矩阵、积分/求和、希腊字母、CJK `\text{}`、颜色/尺寸/布局包装，以及未知命令。
5. 检查导出中的字体预载、公式分页、单个超高公式缩放、表格单元格公式和失败回退。

### 阶段 C：流式、性能与回归

1. 未闭合公式在流式期间保持源文，闭合后渲染；定稿前后不丢字、不改变语义顺序、不产生大幅跳动。
2. 对长消息、多公式和反复重组测量解析/测量开销，避免每帧重复做重型工作。
3. 主题切换、系统字号、窄屏、选择复制和分享/导出均执行回归。
4. 若第三方 renderer 被确认有缺陷，先制作依赖升级或替代原型，单独验证后再决策；不顺带升级无关依赖。

## 5. 测试矩阵

### 输入与语义

- 历史换行防回归：中文句子中穿插 `R_1`、`R_2`、`I-U`、`b`、`k`，保持正文连续自然折行。
- 行内 `$x$`/`\(x\)`；行间独占行 `$$x$$`/`\[x\]`；同一行相邻公式。
- 中英文标点、粗斜体、链接、引用、多层列表、表格单元格。
- 代码围栏、行内代码、转义美元、金额、空/未闭合定界符、未知命令、超长输入。
- 分式、根式、上下标、矩阵、积分、求和、希腊字母、中文文本及现有包装兼容。

### 视觉和交互

- 窄屏手机、常规手机和平板；默认/放大系统字号；浅色、深色及强制主题。
- 检查基线、上下标与分式上下边界、段落行高、容器裁切、透明背景和长公式可达性。
- 检查流式开闭定界符过程；选择复制跨公式内容；屏幕与分享图/导出逐项对照。
- 长消息、多公式列表做滚动流畅度与内存抽查。

## 6. 验收条件

- 截图对应的历史换行样例仍保持行内连续；明确记录为防回归通过/失败，不误报为新发现。
- 支持样例正确排版；未知/畸形输入完整保留，不崩溃、不静默丢失。
- 行内/行间边界、基线、复杂公式、主题、字号、窄屏行为有自动化或可复验截图记录。
- 聊天、选择复制、分享图片和 Markdown 导出内容一致；字体未就绪或无法绘制时有完整 fallback。
- 相关 JVM 测试、Compose/UI 回归与 `assembleDebug` 通过；未覆盖项目明确标注未验证。
- 只有架构决策门有完整对比证据后才替换；方案和迁移成本先记录，再实施。

## 7. 预期触及范围

## 9. 当前状态

本方案范围的实现和上述验收已完成。后续若发现新增语法或具体 renderer 限制，按第 3 节决策门评估；本次通过不代表完整 TeX 标准的所有宏包和命令均受支持。

## 10. 真机复验

手机上的多行块级公式曾保留布局空间却未绘制。公式占位替代文本改为单段后，在原测试对话中确认块级积分和矩阵重新显示。

在 23049RAD8C 手机上用右图的三条公式复测，浅色与深色下均显示胶囊描边及框外小号“已读”。`\fbox`、带固定宽/高和 `\centering` 的 `\framebox`、`\bbox` 背景/边框/圆角均通过布局验证。

修复了分享摘录跳过公式排版的问题。模拟器上的普通分享图与摘录分享图对同一段行内分式及块级积分生成了相同的正文像素，整段分享的长图和分页回归均通过。
