## 48.1 结论

| # | 问题 | 结论 |
|---|---|---|
| 1 | 收藏对象 | 只做**消息级**。不做会话级收藏，也不新增会话置顶 |
| 2 | 分类 | 多收藏夹；可新建 / 重命名 / 删除；内置「默认收藏夹」不可删 |
| 3 | 归属 | **一条消息可同时属于多个夹**。夹 = 归类，不是副本 |
| 4 | 取消的粒度 | 分两级：**从某个夹移除**（轻）与**取消收藏**（清空全部归属、删副本） |
| 5 | 标签 | **不做**。夹已经是多对多分类，再加标签是同义重复 |
| 6 | 数据模型 | **4 张表**：`favorites` / `favorite_folders` / `favorite_memberships` / `favorite_media`；Room 版本 17 → **18** |
| 7 | 唯一约束 | `favorites.messageId` 唯一（一条消息只有一份副本）；`favorite_memberships(favoriteId, folderId)` 复合主键（多夹） |
| 8 | 外键 | **不建**。收藏是用户资产，不随会话删除 |
| 9 | 正文 | 快照收藏时刻的正文（≤ 10 万字）+ 独立预览列（280 字），编辑不跟随 |
| 10 | 图片 | **收藏包含图片**：图片清单存 JSON（以 `path` 引用落盘文件），列表显示 64dp 封面 + `+N`，点开全屏查看 |
| 11 | 图片字节 | **不复制**，靠 `favorite_media` 引用表保活：删会话不删这些文件 |
| 12 | 文本附件 | **不保存**。正文与元数据都不复制，只把文件名记进 `attachmentNames` |
| 13 | 分支 | **跨分支保留**。收藏挂 `messageId`，不挂路径 |
| 14 | 主入口 | 抽屉底部**与「设置」并列**的两格：`[🔖 收藏] [⚙ 设置]` |
| 15 | 消息入口 | AI 操作栏**「删除」右边**加收藏按钮：单击进默认夹，长按弹底部面板 |
| 16 | 用户消息 | 没有操作栏（既有设计），入口在长按菜单（第 2 项） |
| 17 | 底部面板 | 自绘贴底面板（`Dialog`，同 `SourceSheet`），**多选勾选、即时生效** |
| 18 | 分组 | 两种：按会话（默认）/ 按收藏夹；按夹分组时一条消息会在多个组出现 |
| 19 | 搜索 | 搜收藏正文全文 + 备注 + 会话标题 + 夹名；命中片段围绕关键词取窗口 |
| 20 | 跳转 | **复用 `searchTarget` 通道**（只补三处，见 §48.8） |
| 21 | 导出 | 复用多选分享管线；Markdown 里图片只留占位说明 |
| 22 | 备份 | 顶层 `favoriteFolders` + `favorites[].folderIds` + 图片内联；**不升 `BackupFile.VERSION`** |
| 23 | 生命周期 | **删会话不删收藏**（正文 + 图片）。收藏定位为**一份额外的备份**，但不替代 JSON 备份（夹结构、消息树只存在库里） |

一句话：**收藏是「用户挑出来的正文副本 + 它的图片」，夹是这份副本可以同时挂的多个标签页。**
副本只有一份，归类可以有很多个。

## 48.2 背景与目标

### 48.2.1 背景

主用途是长文本创作（[01-PRD](01-PRD.md) §1.1）。写到几十轮后，真正想留住的是**片段**：
一句世界观、一段满意的开头、一个突然想到的转折 —— 以及配图。

现在的四条路各有缺口：

| 现有能力 | 缺口 |
|---|---|
| 滚动翻找 | 长会话几百条，翻不动 |
| 全文搜索（§22.2） | 要先想起关键词。收藏的价值恰是「想不起关键词但记得有这句」 |
| 从这里新建对话（§21） | 把片段复制成新会话，代价太大，还会污染会话列表 |
| 复制到剪贴板 | 只有一格，跨会话、跨天就没了；图片根本复制不走 |

收藏夹解决的是再上一层的问题：**攒到 50 条以后，「按时间倒序的一条长列表」本身就是新的翻找负担。**
而在真实用法里，同一段文字常常同时属于两类：既是「人物设定」，也是「第三章素材」——
所以夹必须是**多对多**，不能是「一条一句归属」。

### 48.2.2 目标

1. 任意一条已完成消息：AI 回复一次点击完成收藏；用户消息两次。
2. 不离开聊天页就能把这条挂到**任意多个**夹（长按按钮 → 面板里勾）。
3. 抽屉一步打开收藏页；可在「按会话」「按收藏夹」之间切换并折叠分组。
4. 搜索命中收藏正文的**任何位置**，并显示命中片段。
5. 收藏里的图片：列表能看到封面、点开能看大图；**会话删了图还在**。
6. 点一条收藏，跨会话跳回原消息并定位；不在当前分支时切回它的分支。
7. 原消息被编辑 / 删除、会话进回收站**乃至彻底删除**之后，收藏仍可读、可复制、可导出。
8. 收藏、夹、图片随备份走：换机恢复后结构不变。

「收藏」的定位是**一份额外的备份**：正文与图片都能独立存活于原会话之外。它不是完整备份 ——
夹结构、消息树、分支只存在库里，要整体搬迁仍得用 JSON 备份（§48.12）。

### 48.2.3 非目标

| 不做 | 理由 |
|---|---|
| 会话级收藏 / 第二种置顶 | 与 `conversations.pinned` 是同一件事的两种说法（同 §21.1 的判断） |
| 标签 | 夹已是多对多；再加一层「能挂多个的东西」，用户要在两套分类体系之间选 |
| 夹的嵌套 | 两级结构会让「这条在哪」变成一次树搜索；50 个扁平夹够用 |
| 收藏图片的裁剪 / 编辑 | 编辑原图的入口在会话里；收藏是只读副本 |
| 复制图片字节 | 与消息共用同一批文件，靠引用表保活（§48.5.5） |
| 保存文本 / 文档附件 | 正文单份可达十万字，元数据也没有复用价值；只留文件名（§48.5.3） |
| 收藏思考内容 | 与 Markdown 导出同一取舍（§22.1） |
| 云同步 / 跨设备 | [01-PRD](01-PRD.md) §1.3 的 Non-Goals |
| 单条收藏的「导出」按钮 | 与 §29.5「单条消息导出明确不做」冲突；单条用「复制」 |
| 收藏计数红点 | 收藏不是任务，不需要催 |

## 48.3 用户场景

| # | 场景 | 现在 | 有了收藏夹 |
|---|---|---|---|
| S1 | 写第三章时想引用第一章那句设定 | 滑很久 | 抽屉 → 收藏 → 按会话 → 点那条 |
| S2 | 同一段既算「人物设定」又算「第三章素材」 | 只能二选一（或复制两份） | 面板里两个都勾上，一份副本两处可见 |
| S3 | 攒了 80 条，想只看「人物设定」 | 一条条翻 | 按收藏夹分组 → 展开「人物设定」 |
| S4 | 正在写，看到一张满意的图 + 一句配文 | 只能截图存相册，和对话断了联系 | 收藏；列表有封面，点开看原图 |
| S5 | 整理会话时删了整条旧会话 | 挑出来的句子和图一起没了 | 收藏里还在（快照 + 图片文件保活） |
| S6 | 记得某句台词但忘了在哪条会话 | 只能搜会话正文 | 收藏页搜索「台词」→ 命中片段直接可读 |
| S7 | 换手机 | 靠 JSON 备份 | 备份带夹、归属与图片 |

S5 已定案：**保留**，收藏按「一份额外的备份」来定位（§48.12）。

## 48.4 交互流程

### 48.4.1 三处入口

```text
① 抽屉底部（与「设置」并列）
   ┌─────────────────────────────┐
   │ 🔖 收藏        │        ⚙ 设置 │
   └─────────────────────────────┘

② AI 回复下方操作栏（删除右边新增）
   ‹1/2›  📋  ▶  🔊  ✏️  🗑  🔖        …（弹性空白）…  🔄
                               ↑单击 = 收藏到默认夹 / 取消收藏
                               ↑长按 = 底部「收藏夹」面板（多选）

③ 长按消息菜单（两种角色都有；用户消息只能走这里）
   复制 / 收藏·取消收藏 / 选择文本 / 分享 / … / 从这里新建对话 / ─── / 删除
```

用户消息没有第二个入口：用户气泡一直**没有操作栏**（§15.3、§28.1 明确的选择），
长按菜单已有 7 项。用户消息要挂多个夹时，走收藏页行菜单「收藏夹…」。

### 48.4.2 收藏动作与状态

| 触发 | 当前状态 | 行为 |
|---|---|---|
| 操作栏按钮**单击** | 未收藏 | 加入默认夹，`Toast`「已收藏到「默认收藏夹」」 |
| 操作栏按钮**单击** | 已收藏 | **取消收藏**（清空全部归属），`Toast`「已取消收藏（含 3 个收藏夹）」 |
| 操作栏按钮**长按** | 任意 | 打开面板；面板内勾选即时生效（§48.4.3） |
| 长按消息 →「收藏」 | 未收藏 | 加入默认夹 |
| 长按消息 →「取消收藏」 | 已收藏 | 取消收藏（全部） |
| 收藏页行菜单「收藏夹…」 | 任意 | 打开同一个面板 |
| 面板内点某个夹 | 不属于 | 加入该夹，行上勾亮起 |
| 面板内点某个夹 | 已属于 | **只从该夹移除**；若移除后没有归属，则整条取消收藏 |

「取消收藏」与「从某个夹移除」是两件事，文案必须分开：前者删副本（含备注与图片登记），
后者只撕掉一个归类。批量操作里两者都有（§48.10.5）。

按钮形态：

| 状态 | 图标 | 颜色 |
|---|---|---|
| 未收藏 | `AppIcons.Bookmark` | `colors.processText` |
| 已收藏 | `AppIcons.BookmarkCheck` | `MaterialTheme.colorScheme.primary` |

按钮**不显示夹数量**：30dp 的圆里塞数字会挤成一团，夹数量在面板与收藏页里看。

流式中的回复没有收藏入口（`actionable = !streaming`，§17.3），避免收藏半截内容。

### 48.4.3 底部「收藏夹」面板

```text
                          ┌───────────────────────────────┐
   （对话页，压暗）        │  收藏夹                  ✕   │
                          │  ☑ 默认收藏夹          12     │
                          │  ☑ 人物设定             7     │
                          │  ☐ 灵感                 3     │
                          │  ☑ 世界观               0     │
                          │  ───────────────────────────  │
                          │  ＋ 新建收藏夹                 │
                          │  ⚙ 管理收藏夹        [完成]   │
                          └───────────────────────────────┘
```

| 项 | 规则 |
|---|---|
| 出现 | 长按操作栏按钮；或收藏页行菜单「收藏夹…」 |
| 勾选 | **即时生效**：点一下写库、更新勾，面板不关。挂三个夹就是三下 |
| 取消勾选 | 只移除这一个归属；移除最后一个时行整体消失，`Toast`「已从全部收藏夹移除」 |
| 新建 | 弹 `AppTextInputDialog`；创建后**自动勾上**并把面板滚到它 |
| 管理 | 关闭面板，跳收藏夹管理页 |
| 完成 | 关闭面板（勾选已经落库，没有「取消」语义） |
| 高度 | 内容自适应，上限**屏高 70%**，超出时列表内部滚动（动作行固定在最下） |
| 排序 | `sortOrder`，默认夹第一 |
| 关闭 | 点遮罩 / 点 ✕ / 点「完成」/ 返回键 |

实现方式是**自绘贴底面板**，与已有的 `SourceSheet`（`ui/chat/SourceSheet.kt`）同一套：
`Dialog(usePlatformDefaultWidth = false, decorFitsSystemWindows = false)` + 全屏
`colors.scrim`（整层可点关闭）+ 贴底 `Column`（上两角 24dp、`colors.card`、
`navigationBarsPadding`、卡片内点击吞掉）。三点好处：

- **不用 `ModalBottomSheet`**：它自带满宽、蒙版、拖拽把手，摆进本应用像外来组件
  （§25.5 的结论、`Attachments.kt` 的注释）。
- **不存在 §34.7 那种命中遮挡**：`Dialog` 是独立窗口，不会把兄弟挡在命中路径外。
- **返回键天然正确**：返回触发 `onDismissRequest`，不必往 §15.7 的链路里再加一层。

把 `SourceSheet` 里那层「scrim + 贴底卡片 + 高度上限 + 吞点击」抽成
`ui/common/BottomSheet.kt`，两处共用；不改视觉。

### 48.4.4 收藏页：两种分组 + 搜索

```text
┌ 顶栏 ────────────────────────────────────────┐
│ (←)  收藏              [分组切换]  [⋯]        │  按会话 ⇄ 按收藏夹
├ 搜索框 ──────────────────────────────────────┤
│ 🔍 搜索收藏内容…                              │
│ [全部]  [我]  [AI]                            │  角色筛选（有收藏时显示）
├ 列表 ────────────────────────────────────────┤
│ ▾ 第一章 · 第六章草稿                 8 条    │  组头（按会话）
│    [图] 我 · 11-27  那句话是这么写的…         │
│          AI · 11-26 「风从北面来…」     [图]  │
│ ▸ 人物小传                            3 条    │  折叠
│ ▾ 默认收藏夹                         12 条    │  组头（按收藏夹）
│    …                                          │
└──────────────────────────────────────────────┘
```

| 模式 | 组头 | 组序 | 组内序 | 空组 | 同一条出现几次 |
|---|---|---|---|---|---|
| 按会话（默认） | 会话标题 + 条数 | 组内最近收藏时间倒序 | 收藏时间倒序 | 不显示 | 1 次 |
| 按收藏夹 | 夹名 + 条数 | `sortOrder`（默认夹第一） | 收藏时间倒序 | **显示**「0 条」 | **每个所属夹各 1 次** |

两条必须写清的后果：

- **按夹分组时一条会出现多次。** 这是分类视图的固有结果（同相册应用）。行尾用
  `Space.Inline` 小字标「另在 1 个夹」，避免用户以为收藏出了重复行。
- **按夹分组必须显示空夹。** 那一屏是这个功能的「结构视图」，隐藏空夹会让人以为夹没了。

搜索态（输入非空）：

- **平铺、不分组、不重复**：一条收藏只出现一次，行尾显示它所属的全部夹名。
- 命中范围：收藏正文全文（`content`）、备注、会话标题、夹名。
- 片段：SQL 里围绕命中处开窗，再交给已有的 `snippetAround()` 压平与补省略号（§22.2）。
- 上限 100 条；超出提示「补充关键词」。

折叠状态只记在 ViewModel（离开页面即重置）；分组偏好写 DataStore
（`favorites_group_mode`），下次打开还是上次那一种。

### 48.4.5 收藏夹管理

入口：收藏页顶栏 ⋯ →「管理收藏夹」；底部面板 →「管理收藏夹」。
落点：`Route.FAVORITE_FOLDERS(depth = 2)`。

```text
(←)  收藏夹                            ＋
──────────────────────────────────────
默认收藏夹        12 条        默认     ⋯
人物设定           7 条                 ⋯
灵感               3 条                 ⋯
```

| 动作 | 规则 |
|---|---|
| 新建 | ≤ 20 字、去空白后非空、不与他人重名、上限 50 个 |
| 重命名 | 同上校验；默认夹**可改名**（它只是默认落点，不是固定文字） |
| 删除 | 确认框写明两种去向：只在这个夹里的 N 条会移到默认夹；另外 M 条还在别的夹里，只少一个归属 |
| 默认夹 | 没有「删除」项；行尾「默认」小字 |
| 排序 | MVP 用 `sortOrder`（创建顺序），不提供拖动；P1 再加 |

### 48.4.6 状态图

```text
未收藏 ──单击按钮/菜单「收藏」──▶ 已收藏（默认夹）
                                    │
                                    ├─面板勾选──▶ 已收藏（N 个夹，N ≥ 1）
                                    │    └─取消最后一个勾──▶ 未收藏
                                    ├─删除所在夹（唯一归属）──▶ 已收藏（默认夹）
                                    └─单击按钮/菜单「取消收藏」──▶ 未收藏

收藏页 ──分组切换──▶ 按会话 ⇄ 按收藏夹
       ──输入关键词──▶ 搜索态（平铺、不重复）──清空──▶ 原分组
       ──进入多选──▶ 多选态 ──取消全选/返回──▶ 列表
```

## 48.5 数据模型与迁移

### 48.5.1 四张表

```sql
CREATE TABLE IF NOT EXISTS `favorite_folders` (
  `id`        TEXT NOT NULL,
  `name`      TEXT NOT NULL,
  `sortOrder` INTEGER NOT NULL DEFAULT 0,
  `createdAt` INTEGER NOT NULL,
  `updatedAt` INTEGER NOT NULL,
  PRIMARY KEY(`id`)
);

-- 一份副本。一条消息只有一行（messageId 唯一）。
CREATE TABLE IF NOT EXISTS `favorites` (
  `id`                TEXT NOT NULL,
  `messageId`         TEXT,
  `conversationId`    TEXT NOT NULL,
  `conversationTitle` TEXT NOT NULL,
  `role`              TEXT NOT NULL,
  `content`           TEXT NOT NULL,
  `preview`           TEXT NOT NULL,
  `note`              TEXT,
  -- 只存图片附件（JSON，见 §48.5.3）：以 path 引用磁盘文件，不复制字节
  `attachments`       TEXT,
  -- 第一张图的 Attachment JSON（约 300 字节），列表画封面用
  `coverImage`        TEXT,
  `imageCount`        INTEGER NOT NULL DEFAULT 0,
  -- 文本 / 文档附件的**文件名**（JSON 数组）。正文与元数据都不保存，见 §48.5.3
  `attachmentNames`   TEXT,
  `messageCreatedAt`  INTEGER NOT NULL,
  `createdAt`         INTEGER NOT NULL,
  PRIMARY KEY(`id`)
);

-- 多对多：一条收藏可以挂多个夹。
CREATE TABLE IF NOT EXISTS `favorite_memberships` (
  `favoriteId` TEXT NOT NULL,
  `folderId`   TEXT NOT NULL,
  `addedAt`    INTEGER NOT NULL,
  PRIMARY KEY(`favoriteId`, `folderId`)
);

-- 图片文件的引用登记：删会话时据此**不删**这些文件（同 attachment_refs 的思路）。
CREATE TABLE IF NOT EXISTS `favorite_media` (
  `path`       TEXT NOT NULL,
  `favoriteId` TEXT NOT NULL,
  PRIMARY KEY(`path`, `favoriteId`)
);

CREATE UNIQUE INDEX IF NOT EXISTS `index_favorites_messageId` ON `favorites` (`messageId`);
CREATE INDEX IF NOT EXISTS `index_favorites_createdAt` ON `favorites` (`createdAt`);
CREATE INDEX IF NOT EXISTS `index_favorites_conversationId` ON `favorites` (`conversationId`);
CREATE INDEX IF NOT EXISTS `index_favorite_memberships_folder` ON `favorite_memberships` (`folderId`, `addedAt`);
CREATE INDEX IF NOT EXISTS `index_favorite_memberships_favorite` ON `favorite_memberships` (`favoriteId`);
CREATE INDEX IF NOT EXISTS `index_favorite_folders_sortOrder` ON `favorite_folders` (`sortOrder`);
CREATE INDEX IF NOT EXISTS `index_favorite_media_favorite` ON `favorite_media` (`favoriteId`);
```

> 真相是 Room 生成的 `app/schemas/com.simplechat.app.db.AppDatabase/18.json`
> （`exportSchema = true`）。上面这份是给人读的版本，处理方式同 §4.2。

### 48.5.2 为什么是「一份副本 + 关系表」

| 方案 | 问题 |
|---|---|
| `favorites.folderId` 单列（上一版） | 一条只能进一个夹，与真实用法冲突 |
| 每个夹各存一份副本 | 备注、图片登记、快照全部分叉；改一次备注要改 N 行，删会话要处理 N 份孤儿 |
| **一份副本 + `favorite_memberships`** | 正文与图片只有一份；归类是纯关系；删夹只删关系行 |

`favorites.messageId` 仍然唯一 —— 它与「多夹」不矛盾：**唯一的是副本，不是归类。**

### 48.5.3 附件：图片存，文本附件不存

`favorites.attachments` 只存**图片**（`List<Attachment>` 的 JSON，与 `messages.attachments`
同一个 `@Serializable` 类型，见 §23.7），图片的 `data`（base64）清空、只留
`kind / name / mime / path / width / height`。

**文本 / 文档附件不保存**（md / txt / docx 抽出、PDF 页）：正文不复制，元数据也不复制，
只在 `attachmentNames` 里记一个文件名，用于告诉用户「这条原本还带了个 `设定.md`」。

| 附件类型 | 存什么 | 不存什么 |
|---|---|---|
| 图片 | `path / width / height / mime / name` | `data`（base64） |
| 文本 / 文档 | 只有文件名（进 `attachmentNames`） | 正文、字数、mime —— 一律不存 |

图片的 `path` 指向 `filesDir/attachments/<uuid>.<ext>` —— 与消息共用同一批文件，**不复制字节**。
写入时若原附件是内联的（`path == null`，老数据或用户粘贴的图），先用
`AttachmentFiles.save(...)` 落盘再存 `path`，否则收藏行会塞进几百 KB 的 base64。

- `attachments` 里只有图片，清单很小（几十张也不到 32 KB）；
- `coverImage` 单独存第一张图，列表查询只读它（§48.13）；
- 文件缺失时按既有约定显示「原件缺失」占位，不崩（§23.8）；
- 文本附件的正文在会话删除后**永久不可得**，这是「不存」的直接代价，写进 §48.11。

### 48.5.4 默认收藏夹

| 项 | 值 |
|---|---|
| `id` | 常量 `FavoriteFolders.DefaultId = "default"` |
| 初始名 | 「默认收藏夹」（字符串资源） |
| 创建 | 迁移里 `INSERT OR IGNORE`；Repository 每次读 / 写前再调一次 `ensureDefaultFolder()` |
| 删除 | **不允许**（UI 无入口，DAO 侧 `DELETE ... WHERE id != 'default'` 再兜一层） |
| 改名 | 允许 |

名字随语言的处理：迁移拿不到资源，先写英文兜底 `Default`；`ensureDefaultFolder(localizedName)`
看到这个名字就替换成当前语言。纯字符串比较，可单测。

### 48.5.5 图片文件的生命周期

这是「收藏含图片」的核心，四件事必须同时成立：

| 场景 | 规则 |
|---|---|
| 收藏时 | 图片 `path` 登记进 `favorite_media(path, favoriteId)` |
| 删会话 / 消息 | **不删**这些文件：`deleteConversations` 目前的判据是「引用表里没有 && 消息里没引用」，再加一条「收藏引用表里没有」 |
| 取消收藏 | 删 `favorite_media` 行；若该 `path` 在 `attachment_refs` 与 `messages` 里也无引用，才删文件 |
| 文件已被清掉 | 占位显示「原件缺失」，不崩、不影响跳转与复制 |

`favorite_media` 与 `attachment_refs`（§23.8）是同一套思路的第二个实例：
**删除时只查这张小表，绝不去读几兆的 JSON。** 代价是每条图片多一行（几十字节）。

### 48.5.6 唯一约束与幂等

| 约束 | 作用 |
|---|---|
| `UNIQUE(favorites.messageId)` | 一条消息只收藏一次。重复收藏 `INSERT OR IGNORE`；多出来的是归属，不是副本 |
| `PRIMARY KEY(favorite_memberships.favoriteId, folderId)` | 同一夹不重复挂 |
| `NULL messageId` | 消息彻底删除后置空；SQLite 把多个 NULL 视为互不相同，所以「仅快照」行不受唯一约束限制 |

重复收藏不更新 `createdAt`、不覆盖备注、**不改归属**：要挂第二个夹是面板里的一次勾选，
不是「再收藏一次」。

### 48.5.7 为什么没有外键

| 候选外键 | 加上会发生什么 | 结论 |
|---|---|---|
| `memberships → favorites / favorite_folders` CASCADE | 删夹会把里面的收藏一起删掉（应当只删关系） | **不加** |
| `favorites.messageId → messages` SET NULL | 语义对，但 Room 迁移要逐字对齐可空列约束 | **不加** |
| `favorite_media.path → 文件` | 文件系统没有外键 | **不加** |

代价：清理与搬移全靠 Repository 显式做（§48.6.4）。换来的保证是
**没有任何一条 SQL 能顺手删掉收藏。**

### 48.5.9 备份格式

```jsonc
{
  "format": "simplechat-backup",
  "version": 2,
  "exportedAt": 1758...,
  "conversations": [ /* 不变 */ ],
  "presets": [ /* 不变 */ ],
  "favoriteFolders": [
    { "id": "default", "name": "默认收藏夹", "sortOrder": 0,
      "createdAt": 0, "updatedAt": 0 }
  ],
  "favorites": [{
    "id": "…", "messageId": "…", "conversationId": "…",
    "conversationTitle": "第一章", "role": "assistant",
    "content": "正文快照", "note": "转折点",
    // 归属：一条可以有多个
    "folderIds": ["default", "ideas"],
    // 图片在这里**内联 base64**（导出时从磁盘读回），否则换机会丢图
    "attachments": [{ "kind": "IMAGE", "name": "p1.jpg", "mime": "image/jpeg",
                      "data": "/9j/4AAQ…", "width": 1080, "height": 1440 }],
    // 文本附件的**文件名**（正文本来就没存，所以这里也只有名字）
    "attachmentNames": ["设定.md"],
    "messageCreatedAt": 0, "createdAt": 0
  }]
}
```

| 情形 | 行为 |
|---|---|
| 旧备份（无两字段）→ 新版 | 只有默认夹、没有收藏。**不报错** |
| 新备份 → 旧版 | 忽略两字段，其余数据正常。**只丢收藏与夹** |
| 新备份 → 新版 | 夹按 `id` upsert；收藏按 `id` upsert；成员关系按 `folderIds` 重建 |
| `folderIds` 里有本机不存在的夹 | 建关系时跳过；若一条都不剩，挂到默认夹 |
| 图片导入 | 写盘 → 新 `path` → 改清单 → 登记 `favorite_media`；同 `path` 已存在时复用 |
| 单会话导出 | **不带收藏、不带夹**（同「不带全局预设」） |
| ZIP 归档 | 自动带上；`manifest.json` 增两个计数 |

**为什么不升 `version`**：`OwnBackupStream.open()` 对版本做严格相等校验
（`check(version == BackupFile.VERSION)`）。升到 3 会让**旧版 App 拒绝导入新备份**，
整套数据都进不去。不升版本时旧版只忽略多出来的字段（`ignoreUnknownKeys = true`）。
附件、`timeline`、`compactions` 三次加字段都是这么办的（§14.4）。

**代价要说清**：备份体积会增加「被收藏图片」的总量（收藏的图片在消息里可能已有一份
内联副本，这次是第二份）。这是「换机不丢图」必须付的钱；P1 可加「备份不含收藏图片」开关。

组头（按会话）：

```sql
SELECT f.conversationId AS id,
       COALESCE(c.title, f.conversationTitle) AS title,
       COUNT(*) AS count, MAX(f.createdAt) AS lastAt
FROM favorites f
LEFT JOIN conversations c ON c.id = f.conversationId
GROUP BY f.conversationId

```

组内（按夹；列表**不读 `content` 与 `attachments`**）：

```sql
SELECT f.id, f.messageId, f.conversationId, f.role, f.preview, f.note,
       f.coverImage, f.imageCount, f.attachmentNames,
       f.messageCreatedAt, f.createdAt,
       (SELECT COUNT(*) - 1 FROM favorite_memberships m2 WHERE m2.favoriteId = f.id) AS otherFolders
FROM favorites f
JOIN favorite_memberships m ON m.favoriteId = f.id
WHERE m.folderId = :folderId
ORDER BY f.createdAt DESC
LIMIT :limit
```

搜索（命中正文任意位置；一条只出一次，夹名用 `group_concat`）：

```sql
SELECT f.id, f.messageId, f.conversationId, f.role, f.preview, f.note,
       f.coverImage, f.imageCount, f.createdAt, f.messageCreatedAt,
       COALESCE(c.title, f.conversationTitle) AS conversationTitle,
       (SELECT group_concat(d.name, ' · ')
        FROM favorite_memberships m JOIN favorite_folders d ON d.id = m.folderId
        WHERE m.favoriteId = f.id) AS folderNames,
       CASE WHEN instr(lower(f.content), lower(:query)) > 0
            THEN substr(f.content,
                        max(1, instr(lower(f.content), lower(:query)) - 40),
                        max(160, length(:query) + 80))
       END AS snippet
FROM favorites f
LEFT JOIN conversations c ON c.id = f.conversationId
WHERE length(:query) > 0
  AND (:role = '' OR f.role = :role)
  AND (instr(lower(f.content), lower(:query)) > 0
       OR instr(lower(COALESCE(f.note, '')), lower(:query)) > 0
       OR instr(lower(COALESCE(c.title, f.conversationTitle)), lower(:query)) > 0
       OR EXISTS (SELECT 1 FROM favorite_memberships m
                  JOIN favorite_folders d ON d.id = m.folderId
                  WHERE m.favoriteId = f.id AND instr(lower(d.name), lower(:query)) > 0))
ORDER BY f.createdAt DESC
LIMIT :limit
```

三处刻意的写法：

- **`instr(lower(…))` 而不是 `LIKE '%…%'`**：`%` 与 `_` 在 LIKE 里是通配符，搜 `100%`
  会变成「100 加任意内容」。仓库里已有同口径测试。
- **片段在 SQL 里开窗**：整条正文可能十万字，先切到 160–200 字，再交给 `snippetAround()`。
- **状态算出来，不存**（`LIVE` / `TRASHED` / `GONE` / `CONVERSATION_TRASHED`）：
  存一份就要在删除、恢复、导入、删夹四条路径上同步（§4.2 的两处真相）。

### 48.7.1 总表

| 事件 | 收藏行 | 归属 | 图片 | 点一条 |

| 编辑原消息（「保存」原地改） | 不变 | 不变 | 不变 | 跳到原文看到改后正文 |
| 「保存并发送」/ 重新生成 | 不变 | 不变 | 不变 | 跳到那一版 |
| 原消息进回收站 | 保留 | 保留 | 保留 | 提示 +「去回收站」 |
| 消息被彻底删除 | 保留，`messageId` 置空 | 保留 | **保留** | 只读：复制 / 看图 / 导出 |
| 会话进回收站 | 保留 | 保留 | 保留 | 提示 +「恢复会话」 |
| 会话彻底删除 / 15 天清理 | 保留，`messageId` 置空 | 保留 | **保留**（引用表保活） | 只读 |
| 切到别的分支 | 不变 | 不变 | 不变 | 跳到该消息并切回它的分支 |
| 勾上/取消一个夹 | 不变 | 变 | 不变 | 正常 |
| 删除所在夹（唯一归属） | 保留 | 补到默认夹 | 保留 | 正常 |
| 取消收藏 | 删除 | 全部删除 | 无人引用时删文件 | — |
| 「删除所有历史对话」 | 全部删除 | 全部删除 | 全部清理 | — |

「文本附件」这一列不存在：它从收藏写入那一刻起就没被保存，所以全表的每一行都不必为它
做取舍。会话删除之后，原消息里的 `设定.md` 只能从会话本身找回 —— 这是「不存」的直接代价。

### 48.7.2 为什么跨分支保留

收藏挂 `messageId`，切版本只改同父兄弟的 `active`（§18.2），两件事不相交 —— 免费。

### 48.7.3 为什么保存快照

1. **删除后仍可读。** 没有快照，收藏会在整理会话时静默失效。
2. **列表不必读 `messages.content`。** 否则一页 50 行正文，撞 `CursorWindow`（§23.8）。
3. **导出的东西与看到的一致。** 用户收藏的是当时那一版。

代价：编辑不跟随（P1 给「用当前正文更新快照」）；单条正文最多 10 万字符
（与 `DraftEntity.MaxChars` 同档，§35.4）。

### 48.7.4 快照与预览生成（纯函数，有单测）

`favoritePreview(content)`：统一换行 → 连续空行压到最多一个 → 去首尾空白 →
取前 280 字（按字符，不按字节）→ 截断补 `…`。

`favoriteContent(content)`：统一换行 → 去首尾空白 → `take(100_000)`。不剥 Markdown 标记。

`favoriteAttachments(list)` 返回一对值：`(images, names)`。

- `images`：只收 `isImage` 的附件，保留 `path / width / height / mime / name` 并清空 `data`；
  内联的（`path == null`）由调用方先落盘。
- `names`：只收非图片附件的 `name`，**内容与元数据一律丢弃**。
- 没有图片时 `images` 为空、`coverImage` 为 null；没有文本附件时 `names` 为空。
- 没有任何附件时两处都是 null，收藏行只有正文。

## 48.8 跳转：从收藏回到原消息

### 48.8.1 结论：复用 `searchTarget`，不新造通道

第一版写的是「不能借用 `searchTarget`」，那个判断错了，两处事实也说反了：

| 第一版的说法 | 事实 |
|---|---|
| 「4 秒后补白消失，内容会跳一下」 | **不会。** `searchSpacePx` 只在 `messages.lastOrNull()?.id` 或 `searchPlacementReset` 变化时归零；`dismissSearch()` 不重置它，真正的复位在 `resumeFollowing()`（用户回到底部那一刻，§25.1） |
| 「`openConversation` 的同会话早退会吞掉定位」 | **反了。** 早退条件是 `id == currentConversationId && targetMessageId == null`；带目标时它会走完整切换（`stop()` + 清空 + 重载） |

`searchTarget` 本身没有缺陷。它已经解决了最麻烦的时序：等 `switching` 结束 →
按 key 找下标 → `scrollToItem` → `markSearchReady`。再写一套等于把它抄一遍
（§17.4 那类「两条路维护同一件事」的老陷阱）。

### 48.8.2 三处必须补的改动

| # | 现状 | 改动 |
|---|---|---|
| 1 | 带目标时也走完整切换：`stop()` 会掐掉正在生成的回复，列表还会闪一下 | 同会话走轻量路径：目标在活跃路径 → 只置 `searchTarget`，让界面滚；在非活跃分支 → 先 reveal + `reloadPath`，不重建观察者、不清会话 |
| 2 | `revealSearchMessage` 内部 `check(...)`，失败抛异常，被通用 `catch` 变成「会话加载失败」 | 改返回 `Boolean`；收藏侧拿到 false 就「打开会话 + banner」。搜索侧同样受益 |
| 3 | 空 query 时仍会 `withTimeoutOrNull(4000)` 等一个永不到来的命中 | `query.isEmpty()` 时直接 `finish()` |

### 48.8.3 流程

```text
点一条收藏
  ├─ 跨会话 ── openConversation(cid, messageId, query = "")
  │              └─ 加载完 → searchTarget 生效 → 定位（38% 顶部留白）
  ├─ 同会话、在活跃路径 ── 只置 searchTarget（不 stop、不重载）
  ├─ 同会话、在非活跃分支 ── 停流式（切分支的既有语义）
  │                          → revealFavoriteMessage → reloadPath → 定位
  ├─ 会话在回收站 ── 对话框：恢复并打开 / 取消
  ├─ 原消息在回收站 ── 对话框：去回收站 / 取消
  └─ 原消息已删除 ── 对话框：复制快照 / 看图片 / 取消
```

四处细节：

- 定位后 `detached = true`（已有 `SideEffect`），避免流式把视口拽回底部。
- **不做闪烁高亮**：搜索的高亮来自命中范围，收藏没有关键词。38% 留白 + 目标在视口内
  已经足够表明「就是这条」。
- 返回列表底部时 `resumeFollowing()` 会顺带清掉 `searchTarget` 与补白。
- 点封面缩略图**不跳转**：直接开全屏查看器（`AttachmentViewerDialog`），看图不该打断阅读位置。

## 48.9 导出与分享

| 入口 | 范围 | 产出 | 复用 |
|---|---|---|---|
| 收藏页多选 → 导出 MD | 选中 N 条 | `.md` | `MessageShareDocument` + `writeSharedMarkdown` + `MessageShareFiles` |
| 收藏页多选 → 复制文本 | 选中 N 条 | 剪贴板 | 同上（文本分支） |
| 收藏页多选 → 系统分享 | 选中 N 条 | 系统面板 | 同上（`FileProvider` + `cacheDir/shares`） |
| 顶栏 ⋯ → 导出全部（P1） | 全部 | `.md` | 同上，逐条读 |
| 单条 | 1 条 | 不给导出按钮 | 行菜单「复制」；要出文件回原消息用既有「分享」 |
| 图片（P1） | 选中 N 条 | PNG | `NativeShareRender` |

**图片在 Markdown / 文本里只留一行占位**（与 §23.6 一致）：
`（图片：p1.jpg · 1080×1440）`。内嵌 base64 会让文稿没法读，要连图带走用备份。

**每组前加一行来源**：`> 默认收藏夹 · 第一章 · 2026-11-27`（多个夹时用 ` · ` 连接）。
现在 `MessageShareDocument(title, groups, excerptFooter)` 没有位置放，加一个带默认值的字段：

```kotlin
data class MessageShareDocument(
    val title: String,
    val groups: List<MessageShareGroup>,
    val excerptFooter: List<String> = emptyList(),
    /** 与 groups 同序；空串 = 不显示。收藏导出填「夹名 · 会话 · 日期」。 */
    val groupHeaders: List<String> = emptyList(),
)
```

默认值保证现有分享调用点一行不改。图片渲染器 MVP 忽略该字段。
上限沿用 §19：图片 20 万字符 / 80 页；Markdown 超 10 万字符不进剪贴板；
全部导出时逐条 `bodyById` 边读边写。

## 48.11 边界与异常

| 情形 | 行为 |
|---|---|
| 流式回复 | 操作栏整行不出现，长按菜单也没有收藏项 |
| 正文为空、有图片 | 允许收藏；行显示缩略图 + 「（图片）」 |
| 正文与附件都空（失败回复） | 允许收藏；摘要显示「（空）」 |
| 重复收藏 | `INSERT OR IGNORE`：不新增副本、不改 `createdAt`、不覆盖备注、**不动归属** |
| 面板里取消最后一个归属 | 整条取消收藏（与「取消收藏」同一条路径），`Toast` 说明 |
| 收藏时消息刚被删（竞态） | `NOT_FOUND` → 「这条消息已不存在」，不写脏行 |
| 图片内联（老数据 / 粘贴） | 收藏时先落盘再存 `path`，避免收藏行塞 base64 |
| 图片文件已被清掉 | 占位「原件缺失」，不崩；复制与跳转照常 |
| 只有文本附件、正文为空 | 允许收藏；行显示「（附件：设定.md，未保存）」，摘要为空。**附件本身不存**（§48.5.3） |
| 会话删除后原文的文本附件 | 正文永久不可得（收藏只留文件名）；界面在该行注明「附件未随收藏保存」 |
| 夹名空白 / 超 20 字 / 重名 | 对话框内就地提示，不提交 |
| 夹已达 50 个 | 「新建」置灰 + 说明；「管理」仍可用 |
| 删除夹 | 「只在这个夹」的收藏补到默认夹；其余只少一个归属；**不删收藏、不动图片**（图片登记挂在收藏上，与夹无关） |
| 备注超长 | 限 200 字，落库前 `trim()`；全空白 = 清空 |
| 备注对话框打开时收藏被删 | 按 `id` 更新，影响 0 行即静默放弃 |
| 搜索词含 `%` / `_` | 按字面量处理（`instr` 而非 `LIKE`） |
| 搜索命中在正文深处 | SQL 开窗 + `snippetAround()`，行里能看见关键词 |
| 搜索无结果 | 一行「没有匹配的收藏」，保留搜索框与筛选 |
| 按夹分组时一条出现在多组 | 预期行为；行尾标「另在 N 个夹」 |
| 组内条目过多 | 单组一次读 ≤ 500 条，超出提示用搜索 |
| 备份里的夹缺失 | 归属跳过；一条都不剩则挂默认夹 |
| 备份条目损坏 | 逐条解析，坏的跳过并计入 `ImportReport.failures`（§37.2 对账） |
| 数据库升级失败 | 不设 `fallbackToDestructiveMigration`，宁可崩（§4.2） |

## 48.12 隐私与备份

| 事项 | 结论 |
|---|---|
| 落盘 | 正文与图片清单进 Room；图片沿用 `filesDir/attachments/`；`allowBackup = false`（§19.5） |
| 定位 | **收藏是一份额外的备份**：正文副本 + 图片，删会话不删它们。它**不替代** JSON 备份 —— 夹结构、消息树、分支只存在库里 |
| 外传 | 不外传。收藏与夹不参与任何请求，不进诊断日志 |
| 图片复制 | **不复制**。收藏与消息共用同一份文件，靠引用表保活（§48.5.5） |
| 文本附件 | **不保存**（连元数据）：换机、删会话之后都无法取回，界面上直说（§48.5.3） |
| 删会话是否删收藏 | **不删**（正文快照 + 图片都留）。已定案：保留 |
| 「删除所有历史对话」 | 收藏、归属、图片登记一并清空；无人引用的图片文件删除；自定义夹清空、默认夹保留 |
| 备份文件 | 含收藏正文与图片 → 备份本身即敏感文件，且体积包含收藏图片 |
| 回收站过期清理 | 断链但保留快照与图片，标「来源会话已删除」 |

## 48.13 性能

### 48.13.1 列表与分组

| 关注点 | 处理 |
|---|---|
| 组头 | 按会话：`GROUP BY conversationId`（1e3 量级）；按夹：≤ 50 行 + 计数子查询 |
| 组内 | 展开时才查；`favorite_memberships(folderId, addedAt)` 与 `favorites(conversationId)` 各有索引 |
| 组内上限 | 500 条；超出提示用搜索 |
| 平铺 / 搜索 | keyset 分页 50 行；搜索上限 100 条 |
| 每页字节量 | 行只取 `preview`（≤ 280 字）+ `coverImage`（约 300 字节）→ 一页约 60 KB |
| 大字段 | 列表**永不**读 `content` 与 `attachments`；正文只在复制 / 导出时按 `id` 单条读 |
| 单条读取 | `content ≤ 100 000` 字符（约 300 KB UTF-8）；清单 ≤ 32 KB，单行安全 |
| 缩略图 | `rememberAttachmentImage(cover, targetPx = 64dp)` 按显示尺寸采样，每行最多解码一张 |
| 状态 | 由 `CASE` 表达式算，不做冗余列 |
| 重组 | 行 `key = favoriteId + folderId`（按夹分组时同一条会出现在多个组）；摘要建行时算好 |

### 48.13.2 搜索成本

搜索要扫 `content`。收藏量级小，代价可接受，但要写清上限：

- 500 条 × 平均 5 KB ≈ 2.5 MB，`instr` 一遍是毫秒级；
- 极端 5000 条 × 100 KB = 500 MB，会到百毫秒以上 —— 输入防抖仍然有效，延迟可见；
- 降级方案（不在 MVP）：只搜 `preview`，或给 `content` 建 FTS5（中文要分词器，§22.2 已拒绝）；
- `lower(content)` 会为每行生成小写副本，这是既有全文搜索已在付的成本。

### 48.13.3 10 万级消息下的成本

驱动表永远是 `favorites` / `favorite_memberships`（1e3 量级），`messages` 只按主键回查
≤ 50 行。语料总量只影响主键 B-tree 深度，可忽略。反面写法是拿 `messages` 当驱动表按
`conversationId` 关联收藏 —— 那会扫 10 万行。

### 48.13.4 写、图片与导出

- 收藏 = 1 次单行读 + 1 次清单读 + 1 个事务（副本 + 归属 + 图片登记）。异步做，不阻塞 UI。
- 面板勾选 = 1 行写入（`INSERT OR IGNORE` / `DELETE`），乐观更新勾选态。
- 导出逐条 `bodyById` 边读边写；**不做** `SELECT * FROM favorites WHERE id IN (:ids)`：
  50 行 × 300 KB 会一次性撑爆游标窗口（§23.8 的同款错误）。
- 备份导出图片时逐张 `materialize`，不整批读进内存。

## 48.16 开放问题

> 前两版列的三条已定案：删会话**保留**收藏（视为额外备份，§48.12）、文本附件
> **不保存**（§48.5.3）、收藏总数不设上限。剩下两条真正需要产品决策的。

**1. 收藏要不要提供独立的「导出收藏」包？**

既然它的定位是「一份额外的备份」，只靠全量 JSON 备份带走就有点别扭：想单独备份收藏、
或把收藏挪到另一台设备时，用户必须连全部对话一起导出。做法可以复用 ZIP 归档
（`manifest.json` + 收藏 JSON + 图片），成本约数据层两天；收益是「收藏」这个名字
与它实际的能力对得上。不做也说得通 —— 全量备份本来就能覆盖。

**2. 备份体积与图片的取舍要不要给开关？**

收藏图片会随备份走（§48.5.9），体积可能增加几十 MB。P1 计划加一个「备份不含收藏图片」
的选项；要不要挪进 MVP，取决于对备份大小的敏感度。默认建议：MVP 一律包含
（宁可大，不可丢图），P1 再给开关。
