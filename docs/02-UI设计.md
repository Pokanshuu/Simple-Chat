### 7.2 主题

- 三种模式可切：**跟随系统 / 浅色 / 深色**
- **刻意不做动态取色（Monet / 莫奈取色）。**

  动态取色会把背景、表面、描边全部染上壁纸的颜色 —— 阅读类应用里正文底色的
  色偏直接影响长时间阅读的舒适度，而"跟随壁纸"并不带来任何功能价值，
  只是让界面看起来像别人的应用。

  这里要的是**稳定的中性底 + 一个固定的品牌蓝** `#4D6BFE`：
  正文区永远是干净的近白 / 近黑，品牌色永远可辨认。

  > 早期版本做过"动态取色只作用于表面层、`primary` 恒定品牌蓝"的折中。
  > 真机上一眼看出来：表面层一变，整块界面的气质就不对了。已整体移除。

- 另有 `ChatColors`（`LocalChatColors`）承载 Material 没有的语义色：
  用户气泡、过程文字、卡片、分隔线、危险色、遮罩等。

### 7.3 界面清单

**① 空态**
`☰` ＋ 右侧 `🔕` `⊕` ｜ 中央 LOGO ~56dp ＋「你好，我能帮什么忙吗？」20sp Bold
｜ 底部输入容器：占位「发消息」/ 第二行 `深度思考` 胶囊 ＋ 右侧 `⊕` `🎙` 圆形描边按钮
｜ 页脚「回答由 AI 生成，仅供参考」

> 无语音输入与 TTS（用户确认不做）。`⊕` 仅在模型支持识图时显示。

**② 对话中 · 流式**
用户浅蓝气泡右对齐 → `ProcessPanel` 尾随 4 行 → 输入区右侧蓝色实心圆「停止」按钮

**③ 对话中 · 完成**
ProcessPanel 收成一行：「已深度思考 · 8 秒 · 1,024 tokens ⌄」

**④ AI 回复**
完整 Markdown 渲染；引用块左粗竖线；段落间距约 1em；
底部操作栏：复制 / 重新生成 / 编辑 / 删除；有版本时显示 `‹ 2/3 ›`
右下角白底蓝边圆形「回到底部」悬浮按钮（离开底部时出现）

**⑤ 抽屉**
搜索框（`#F2F3F5` 填充，圆角 12dp）→ 分组「置顶 ⌃」+ 排序图标 →
纯文本列表（行高 64dp）→ 底部固定栏：头像 + 标识 + `···`

**⑥ 多选模式**
`选择对话` + 圆形 X ｜ 每项左圆形 checkbox ｜ 底栏 `置顶 | 删除`

**⑦ 长按菜单**
白卡圆角 16dp + 阴影，锚定在列表项：重命名 / 取消置顶 / 多选 / **删除（红）**

**⑧ 确认对话框**
标题 + 灰色副标题 + 红色胶囊主按钮 + 纯文字取消

**⑨ 设置页**
一级只放入口，具体编辑进二级（实现细节见 §14.5）：

```
账户   数据管理 · API 配置
应用   外观（点击直接弹菜单）· 预设 · 字体大小 · 自动折叠思考内容
关于   关于 SimpleChat
```

一级每项图标各不相同；二级页面里的行不配图标。
「外观」只有三个互斥选项，弹菜单比切页面快，故不进二级。

**⑩ 附件选择流程**

```
点击 ⊕（仅当模型支持识图）
   ↓
输入框下方展开附件面板，⊕ 变为 ✕
   ├─ 媒体网格：横向可滚，缩略图圆角 12dp
   │            每张右上角圆形勾选框（未选=描边圆环，选中=品牌蓝底白勾）
   │            可多选；缩略图左下角显示文件名小标签
   └─ 三个入口按钮：拍照 / 相册 / 文件
                  尺寸约 112×88dp，圆角 12dp，图标 28dp + 文字 14sp
                  「文件」弹出来源菜单（本地文件 / 其他来源）
   ↓ 选中后
输入框内部左上角显示缩略图，右上角 ✕ 可移除
   ↓ 有图片时
输入框下方自动出现快捷指令 chips：
   「分析一下 →」「这是什么 →」「怎么办 →」「解释一下 →」
   描边胶囊，高约 40dp，点击即填入输入框
```

**与官方客户端的差异**：去掉语音输入（`🎙`）与「智能搜索」胶囊。
输入区第二行改为本项目的两个功能入口：

```
[ ⚙ ] [ 深度思考 ⌄ ]  ………………  [ ⊕ ] [ ↑/■ ]
  对话设置   思考档位+模型            附件   发送/停止
```

两者都会在输入栏下方展开面板，**输入栏随之上移**（与选图面板同一机制）。
两个面板互斥；点回输入框或按返回键收起。

**⑪ 思考面板**（点「深度思考」展开）

思考**开关与强度合并为一个 3 档滑块** —— 比「开关 + 强度」两个控件少一次操作，
也与服务端语义一致（`thinking.type` 与 `reasoning_effort` 本就是一件事）：

```
关闭  ────  high  ────  max
 ↑ 最左即关闭
```

- 滑块下方标出三档文案，当前档位高亮
- 说明文字：档位越高，思维链越长、耗时与成本越高
- 模型不支持思考时整个滑块置灰，并说明原因
- 下方接**模型列表**：显示名称 + `id · 识图 · 思考 · 上下文`，当前项高亮带勾
- 右上角「拉取列表」调 `GET /models`（OpenCode Go 无需鉴权；DeepSeek 需 Key）

**⑫ 对话设置面板**（点 ⚙ 展开）

三段式，可滚动（上限 360dp）：

1. **对话模式** —— 复用可拖动分段控件（创作 / 扮演）
2. **系统提示词**
   - 预设列表，可多选、按序拼接（扮演模式下每张预设即一个角色）
   - 会话补充提示词输入框
   - **「预览最终提示词」可折叠展开** —— 创作工具最怕黑盒，
     必须能一眼看到实际拼装并发送出去的内容
3. **采样参数**（严格按服务端真实行为置灰，不是简单禁用）
   - `temperature`：思考模式下置灰，并写明「服务端静默忽略，不报错」
   - `top_p`：仅思考模式启用，范围 0.95–1.0，说明非思考模式下恒为 1.0
   - 注明 `frequency_penalty` / `presence_penalty` 已废弃故未提供

### 7.4 ProcessPanel 规格（思考区）

```
流式中   固定 96dp（4 行），内容底部对齐
         新内容从下方推入，旧内容向上溢出裁切 → 永远只看得到最后 4 行
              ↓
输出结束 平滑收起为一行：「已深度思考 · 8 秒 · 1,024 tokens  ⌄」
              ↓
手动点开 展开完整内容，不再自动折叠
```

组件命名为 `ProcessPanel` 而非 `ThinkingPanel` —— 未来若启用工具调用，
可直接往里塞工具调用卡片行（`🔧 get_weather → 24℃`），复用同一套尾随 + 折叠逻辑，
**不需要改结构**。

## 15. UI 规格（全应用统一）

三套 token，新增界面一律从这里取值，不要再随手写数字。

### 15.1 网格（`Space`）

| token | 值 | 用途 |
|---|---|---|
| `Screen` | 16dp | 屏幕左右安全内边距 |
| `Card` | 16dp | 卡片 / 浮层内部内边距 |
| `Inline` | 12dp | 行内元素之间 |
| `Gap` | 8dp | 组内纵向间距 |
| `Section` | 24dp | 分组之间 |

容器内文字的左边界 = 容器内缩 + `Inline`。抽屉里搜索框、分组标题、
会话行高亮**共用同一个内边距**，左边界必须落在一条竖线上。

### 15.2 圆角（只有四档）

| 形状 | 值 | 用途 |
|---|---|---|
| `PillShape` | 全圆角 | **所有**单行输入框、搜索框、带文字或带箭头的按钮 |
| `SoftShape` | 14dp | 列表行、小卡片、菜单项自身 |
| `MenuShape` | 18dp | 大卡片、浮层菜单 |
| `ContainerShape` | 24dp | 多行容器（输入栏、输入面板） |

消息气泡用 `BubbleShapeOut / In`：靠近发出侧的一角收紧到 6dp，给出方向感。

**搜索框的粗细**（`FieldThickness`，12dp）：胶囊内边距的**纵向**值，抽屉的搜索框与
全屏搜索页的搜索框共用。**以搜索页那条为准**；横向内边距各留各的（抽屉要与分组
标题对齐，见 §15.1）。之前一处 10dp、一处 12dp，两条并排看明显一粗一细。

### 15.3 形状

| 元素 | 形状 |
|---|---|
| **纯图标按钮** | 正圆 |
| **带文字 / 图标 + 箭头的按钮** | 胶囊 |
| 单行输入 | 胶囊 |

> 水波纹一律 `clip` 在 `clickable` **之前**，否则会得到方角水波纹。

### 15.4 阴影（`AppShadow`，两档）

`elevation` 只决定**扩散范围**，浓淡由 `ambient / spot` 的 alpha 单独控制 ——
两者拆开才谈得上"范围大但很淡"。

| | elevation | ambient | spot | 用途 |
|---|---|---|---|---|
| Panel | 5dp | 6% | 10% | 输入栏、输入面板（面积大，略淡一档） |
| Raised | 10dp | 13% | 18% | 菜单、抽屉 |

> **踩过的坑**：两处曾各写各的 —— 输入栏用框架默认色（偏黑 → 太浓），
> 菜单却用 4% 的极淡色（→ 看不见），方向刚好反了。
>
> 浮层内需预留 `MenuShadowBleed`（26dp）绘制空间：`Popup` 的窗口尺寸
> 就等于内容尺寸，阴影画到内容之外的部分会被直接裁掉。

### 15.5 菜单

**全应用唯一实现** `AppMenu`（自绘 `Popup`），不用 Material3 的 `DropdownMenu`：
后者内部注入 `MenuDefaults.VerticalPadding`（8dp）改不掉，且行高固定 48dp、
宽度随内容浮动 —— 抽屉与对话页会长成两个样子。

- 固定宽 208dp；菜单项固定 44dp 行高、图标 18dp
- 总上下内边距 4dp
- **分隔线固定接在危险操作之前**，不随「有没有版本」这类数据变化
- 定位分两种：
  - **点击控件触发** → 锚点下方，**右对齐**锚点右边缘
  - **长按触发** → **跟手**，从手指落点弹出
- 下方放不下翻到上方；横向越界钳回窗口

> 跟手的实现：`combinedClickable` 的 `onLongClick` **不提供坐标**，
> 故用 `PointerEventPass.Initial` 旁听按下位置，**不 `consume()`**，
> 点击 / 水波纹 / 长按照常工作（`rememberPressPosition`）。

### 15.6 滑块的刻度文案

文案中心必须落在**刻度的实际横坐标**上。
用 `Row + weight(1f)` 平分会得到 `(i+0.5)/n` 的中心，而刻度在 `i/n` ——
稳定错半格。`AppSlider(tickLabels = ...)` 内部按刻度坐标逐个居中。

### 15.7 页面转场（`ui/common/Motion.kt`）

**所有页面切换都从 `screenTransform(forward)` 取**，规格只定义一次。

| 项 | 值 | 为什么 |
|---|---|---|
| 时长 | 300ms | 对齐平台 Activity 切换（Material medium 档）。再短"闪一下"，再长拖沓 |
| 缓动 | `FastOutSlowInEasing` | 平台标准的先快后慢 |
| 位移 | **整屏**推 | 与 `@android:transition/slide_left` 一致 |
| 淡入淡出 | **不加** | 见下 |

前进 = 新页从右整屏推入、旧页整屏推向左侧；后退反过来。方向由枚举的 `depth` 判定
（`Route` 与 `SettingsPage` 各带一个 `depth`），同级之间不互跳，所以只比深度就够。

#### 为什么是整屏推、且不叠淡出

先做的是"出场只推 1/3 屏 + 两头淡入淡出"，抓中间帧一看是**糊的**：
两页在中途叠在一起，各自又是半透明，底下的空白透出来 —— 重影 + 发灰。

整屏推则两页**首尾相接、严丝合缝**（任一时刻 A 占 `[-t, 1-t]`、B 占 `[1-t, 2-t]`），
全程没有重叠也没有空档；不带淡出就不存在"半透明叠半透明"。
平台自己的 Activity 切换也是这么做的。

#### 状态存档

`rememberSaveableStateHolder` + 两处 `AnimatedContent`：
页面离开组合后 `rememberSaveable` 的存档会一并丢失，
于是"从设置返回对话就得重新滚到底"。存档本来就是导航组件该管的事 ——
不引导航组件，就得自己接上。

顺带修掉一个真问题：设置页六个二级页原先**共用同一个 scroll state**，
从「设置」滚到底再进「数据管理」，进去就是滚到底的。现在每页各一份。

#### 搜索：把抽屉撑满，不是"切到另一个页面"

点搜索框时**抽屉不关**，同一个面板从 **78% 撑到 100%**，内容换成搜索页。

先前的做法是"关掉抽屉（往左跑）+ 切到搜索路由（从右边推入）" ——
两个方向相反的运动同时发生，看着就是各走各的。而搜索本来就该是
"把抽屉拉开看清楚"，不是"跳到另一个页面"：它的搜索框、它的列表，
都在同一块面板上。

| 元素 | 处理 |
|---|---|
| 面板宽度 | `animateFloatAsState` 0.78 ↔ 1.0 |
| 面板圆角 | `animateDpAsState` 16dp ↔ **0**（撑满还留圆角会在四角露底） |
| 内容 | `Crossfade` 列表 ↔ 搜索（宽度在变，硬切会"闪一下"） |
| 手势 | 撑满时**禁止拖动** —— 那时它已经不是抽屉了，往左拖会拖出一个奇怪的宽度 |
| 搜索态 | 不是一条 `Route`，是抽屉自己的一个状态 |

#### 返回键：**每一层都要有人接**

**这不是可选项。** Compose 的返回事件**没人消费时会一路落空到 Activity 的
`finish()`** —— 用户随手按个返回，App 就直接没了。

同一个坑在**三处**踩到过：

| 层 | 症状 | 谁该接 |
|---|---|---|
| 抽屉打开 | 退出 App | `ModalNavigationDrawer` **不处理返回**（实测；旧版本一直如此） |
| 对话设置 / 思考档位面板 | 退出 App | 面板自己 |
| 修改输入 / AI 回复编辑弹窗 | 退出 App | 各自 |

优先级**从低到高**写（`OnBackPressedDispatcher` 是后添加的先响应）：

```
设置页        → 回对话页
抽屉打开      → 关抽屉
搜索态        → 退出搜索（抽屉保持打开）
面板          → 收起面板
修改输入      → 放弃修改、还原草稿
AI 回复编辑   → 关弹窗
```

**定位手段**：临时插一个 `BackHandler(enabled = true)` 放在**最前面**
（优先级最低）当探针，打一行日志。它响了就说明**没有任何人**接这一层 ——
比盯着代码猜快得多。

### 14.2 列表管理

侧拉抽屉（屏宽 78%）：搜索入口 → 五段分组（置顶 / 今天 / 昨天 / 7 天内 / 更早）
→ 底部固定设置入口。长按出行内菜单，多选模式底部为操作栏。

点搜索框进入**全屏搜索页**（自动聚焦 + 实时过滤 + 关键词高亮）——
抽屉是"浏览"，搜索是"查找"，两者空间需求不同。

### 14.5 设置页结构

一级只放**入口**，具体编辑进二级；一屏内可扫完。

```
账户   数据管理 →（导出 / 导入[合并·覆盖] / 删除全部）
       API 配置 →（服务商 / Base URL / 模型[拉取列表·手动填写] / API Key / 测试连接）
应用   外观     → 直接弹菜单（跟随系统 / 浅色 / 深色）
       预设     →（提示词库的增删改）
       字体大小 →（预览气泡 + 跟随系统开关 + A—A 滑块）
       自动折叠思考内容 → 开关
关于   关于 SimpleChat →（版本 / 开源许可）
```

每个一级入口配**各自不同**的图标；二级页面里的行**不再配图标**，避免图标语义打架。

## 24. 本轮 UI 修正（12 条）

一轮真机反馈。每条记「现象 → 真因 → 修法」，因为**现象常常指向错误的真因**。

### 24.1 抽屉遮罩"没有了"

- **真因**：遮罩取的是 Material 默认的 `colorScheme.scrim`（32% 黑）。
  浅色模式下勉强看得见，**深色模式下盖在近黑底上等于没有**。
  另外抽屉顶部有一条淡紫色带 —— `ModalDrawerSheet` 默认容器色在状态栏
  内边距区域露了出来，而抽屉内容的 `statusBarsPadding` 又叠了一层。
- **修法**：遮罩进 `ChatColors.scrim`，浅色 45% / 深色 62%；
  抽屉容器色改成与内容一致的 `card`，并把 `windowInsets` 交给内容自己处理。
  触发时机不自己写 —— `ModalNavigationDrawer` 本来就按**拖拽位移逐帧插值**，
  从边缘往右拖时遮罩是渐显的。

### 24.2 Markdown 不实时渲染 / 定稿跳版式 / 段间距前后不一致

见 §6.2（改成实时渲染 + 节流）与 §6.5（软换行）。三条现象是**同一个根因**。

### 24.3 会话列表每行太高

行高 56 → 46dp，行的纵向内边距 6 → 2dp，分组标题与搜索框的内边距一并收窄。

### 24.4 全局沉浸式系统栏 + 去掉莫奈取色

- **动态取色整个去掉**。它会把背景、表面、描边全部染上壁纸的颜色 ——
  阅读类应用里正文底色的色偏直接影响长时间阅读的舒适度，而"跟随壁纸"
  不带来任何功能价值。要的是**稳定的中性底 + 一个固定的品牌蓝**。
- 系统栏：`enableEdgeToEdge()` + 各页面自己 `statusBarsPadding` /
  `navigationBarsPadding`。抽屉底部补了手势条内边距（原先"设置"入口被小白条压住）。

### 24.5 点暂停也跳回顶部

同 §24.2 —— 定稿/中断那一瞬间版式重排。改成实时渲染后**像素级一致**，不再跳。

### 24.6 菜单缺少缩放过渡

`AppMenu` 是自绘 `Popup`，原先 `if (!expanded) return` 会在一帧内消失，
根本没有做退出动画的余地。现在多留一个 `mounted` 状态：
`expanded` 变 false 后先把退出动画播完再摘掉 Popup。
缩放支点选**靠锚点那一侧的上角**（点击触发 = 右上，长按跟手 = 左上），
菜单像从触发它的地方"长出来"，而不是从自己中心涨开。
只缩到 1f 为止 —— `Popup` 的窗口就是内容尺寸，放大只会被裁掉。

### 24.7 切换会话应直接看到最底部

`openConversation` 原先**同步**清空列表、**异步**填回来，中间那一帧列表是空的，
界面闪一下空态；而且没有滚到底。

现在：**先读回来再整份替换**（不再先清空），配合一次"快速溶解"（先淡出 90ms
→ 等新内容就位 → 滚到底 → 淡入 160ms）。

滚到底这件事本身也修了三轮，值得记下来：

```kotlin
// ❌ 第一版：读 layoutInfo 算"还差多少"
//    scrollToItem 只是发出滚动请求，layoutInfo 要下一帧才更新，
//    紧接着读拿到的是滚动前的旧值 → 有时落到底、有时停在半路
// ❌ 第二版：给 scrollToItem 传超大 offset
//    实测列表**不夹**，直接滚过头露出底部空白
// ✅ 第三版：scrollToItem + scrollBy(大值)，并**重试到真的到位**
//    scrollBy 会被夹到内容底部；刚组合出来的列表还没量过，
//    scrollToItem 会被丢掉，所以要每轮让出一帧再看一眼
```

### 24.8 展开面板后点别处关不掉

输入栏下方的面板是**内联**的（不是 Popup），点空白处不会关。
现在面板展开时在消息区上盖一层**透明**遮罩，点一下就关，并且**吃掉这一击** ——
否则用户点空白处关面板，顺手还点开了底下那条消息。

### 24.9 删除弹窗样式不统一

设置页里那个「删除全部历史对话」用的是页面**自己**的 `ConfirmDialog`
（横向文字按钮），而对话列表里的删除用的是共享的 `AppConfirmDialog`
（竖排胶囊按钮）。删掉页内实现，统一到共享组件。

### 24.10 中文排版要两端对齐

`MarkdownBodyStyle` 加 `TextAlign.Justify`。中文没有词间空格，天然是
"一格一字"的方块排版 —— 左对齐时右侧参差，一行长一行短，长文读起来很毛躁。

用 `.copy` 而不是另起一份样式：字号、行高仍然只有 `bodyLarge` 一个来源，
**只声明一个刻意的差异**（对齐方式）。

### 24.11 切换会话有点卡

见 §24.7 的溶解。另外「先清空再填」会造成一次空态闪烁，那是"卡"的主要来源。

### 24.12 正文应该能跑到输入框下面被挡住

原先消息列表与输入栏是**上下两块**，列表内容被一条硬边界截断。
现在输入栏**浮在**列表上方（`Box` + `align(BottomCenter)`）：

- 列表底部留白 = 输入区**实测高度**（`onSizeChanged`），最后一条仍滚得出来
- 输入区背后垫一层"透明 → 页面底色"的竖向渐变，正文是**淡出**的，
  而不是从输入栏四周的圆角、以及它下方那段空隙里露出来

## 25. 第二轮真机反馈

### 25.1 流式跟随：**开始滑就停**

- **现象**：生成过程中上翻去看别处，只要**往下滑一点点**，立刻被拽回底部。
- **真因**：判据用的是"上一次滚动的方向"（`lastScrolledBackward`）。
  方向一变就恢复跟随，而流式每 50ms 就来一次内容变化 —— 下一批 token 进来
  直接把人拽到底部。
- **修法**：改成**手指一动就停**，而不是等滑完再判断：

  ```kotlin
  snapshotFlow { listState.isScrollInProgress }.collect { scrolling ->
      if (scrolling) autoFollow = false          // 别跟用户抢
      else if (messages.isEmpty() || listState.isAtBottom()) autoFollow = true
  }
  ```

  等滑完再判断是不够的：判断发生的那一刻，早有一批 token 把列表拽回去了
  （实测：上滑三下，截图仍在最底）。

  另外把"什么时候该跟"收紧成**只有两种情况**：

  | 情况 | 跟不跟 |
  |---|---|
  | 刚追加了新消息 | 跟 |
  | 尾巴正在流式 | 跟 |
  | 换版本 / 编辑 / 删除 | **不跟** |

  否则换个版本、改个字都会莫名跳到底部。

  发消息时**强制恢复跟随** —— 那是明确的"我要看新内容"。

### 25.2 「回到底部」按钮

离开底部时右下角浮出一个小圆钮（40dp、卡片底 + 描边 + 悬浮投影，
`AnimatedVisibility` 缩放入场）。点它 = 回到底部 **+ 恢复自动跟随**。

只在离开底部时出现 —— 一直挂着会平白挡住正文，而它贴底时毫无用处。

### 25.3 切版本停在原处

官方切分支时会**保持当前消息**，不是跳到底部。做法：

1. 切换前记下那条消息**离视口顶部多远**（`visibleItemsInfo.offset`）；
2. `switchVariant` 里 `reloadPath` 之后把 `pathRevision` +1；
3. 界面按 `pathRevision` 变化把位置摆回去（`scrollToItem(index, offset)`）。

`pathRevision` 是必要的：换版本时**列表条数常常不变**，只靠 `messages.size`
分辨不出"这是新内容"还是"换了条分支"。

### 25.4 代码块：展开/收起无效 + 不显示行数

- **现象**：一段 5 行的代码显示成「展开全部（共 24 行）」，点了没反应。
- **真因**：`MarkdownComponentModel.content` 是**整篇文档**，不是那一段代码 ——
  库内部是用 `getTextInNode(node, content)` 切出代码的。
  我直接 `splitFence(model.content)`，于是"行数"数的是全文行数：
  既有 24 行就误判为"需要折叠"，可它本来就没被裁掉，展开自然毫无变化。
- **修法**：从 AST 节点取（`content.substring(node.startOffset, node.endOffset)`）。
- 顺带把行数**总是**显示在顶栏（`python · 36 行`），不再只在折叠时冒出来；
  底部按钮简化为「展开全部（36 行）」/「收起」。

### 25.5 附件入口的容器

点 `⊕` 一开始做成了 Material 的 `ModalBottomSheet`：它自带满宽、自带蒙版、
自带拖拽把手 —— 摆在应用里像个外来的东西，左右顶到屏幕边、和输入栏对不齐，
与输入栏下面那三个面板是两套语言。

现在**复用 `InputPanel`**：浮在输入栏上方的一块圆角卡片，左右 16dp、
与输入栏同宽，共用同一层阴影，也自动获得"点外部关闭"和返回键关闭。

同时 `⊕` 在展开时整体旋转 45°：加号变成叉，"再点一下是收起"就不用另外说明。
转的是**整个按钮** —— 圆形是对称的，看起来就是里头的加号在转，
比"两帧之间换一个图标"顺得多。

### 25.6 应用图标（用户重做）

`ICON.png` 换成新的一版（浅灰气泡 + 深蓝 SC + 蓝色尾巴）。

- **背景层取图标本体色** `#F3F5F8`。前景层里的图形四周是透明的，
  背景用同一个色，启动器把外圈裁成圆 / 方 / 水滴时接缝就看不出来 ——
  看起来是一整块浅底 + 一个蓝尾巴的气泡，而不是"一张图贴在色块上"。
- **前景层整幅铺满** 108dp 画布，**不再往里缩到 72dp 安全区**：
  这张图的四角本来就是透明的，铺满之后蒙版裁掉的是透明区、底下是同色背景，
  看起来是"整块底 + 气泡"；缩到安全区反而会变成"一个小图形浮在大色块中央"。
- 启动图底色同步成 `#F3F5F8`，冷启动时图标与背景连成一片。

> **后来又换过一次**（v0.9.0-beta）：源图改成「圆角方形浅底 + **左上角** SC + 底部蓝尾巴」，
> 五档前景图按同样的约定（整幅铺满、不缩安全区）重新生成。
> 新的已知局限（圆形蒙版会裁到 SC）与三条备选改法见 **§20.3**。

### 25.7 弹窗被键盘挡住

- **现象**：编辑 AI 回复的弹窗，键盘一弹起来就把底部的「保存 / 保存并发送」盖住，点不到。
- **真因**：Compose `Dialog` 的窗口**默认会把系统栏 / 输入法的内边距自己吃掉**
  （`decorFitsSystemWindows = true`）。窗口既然已经"处理"了，Compose 侧再读
  `WindowInsets.ime` 就是 0 —— 里面那句 `imePadding()` 其实是空转。
  这个坑很隐蔽：代码看起来"已经处理了键盘"，却完全没生效。
- **修法**：

  ```kotlin
  Dialog(
      properties = DialogProperties(
          usePlatformDefaultWidth = false,
          decorFitsSystemWindows = false,   // ← 关键
      ),
  )
  ```

  置为 false 让窗口铺到边到边，inset 才会往下传，`imePadding()` 才有值。
  两处带输入的弹窗（编辑 AI 回复、通用文本输入）都补上了。

  > 值得记住的规律：**任何"我明明写了 `imePadding()` 却没反应"的场合，
  > 先看它是不是在 `Dialog` / `Popup` 这类独立窗口里** ——
  > 那种情况下窗口才是 inset 的接受方，Compose 这边拿到的是 0。

## 33. 系统栏沉浸、主题色，以及三个"被借错语义"的地方

> beta.6。三件事：把系统栏从"跟系统"改成"跟 App"；加一个可选主题色；
> 以及收掉三处**语义被借用**导致的观感 bug。§13 的 beta.6 行是本节的摘要。

### 33.1 系统栏（含 MIUI / HyperOS 的「小白条」）为什么不跟 App

`enableEdgeToEdge()` 只做了一件事：让布局伸到系统栏后面。剩下两件它按**系统**来：

1. **系统栏图标的明暗**取自 `detectDarkMode(resources)` = 系统的深浅。本 App 的主题模式
   是独立的（设置页可强制浅色 / 深色），于是「系统浅色 + App 深色」时状态栏图标与
   导航栏「小白条」都会反色 —— 深色底上一排看不见的图标。
2. **导航栏的对比度兜底**。targetSdk ≥ 35 时走 AndroidX 的 `EdgeToEdgeApi35.setUp`，
   其中一句是：

   ```
   window.isNavigationBarContrastEnforced = (navigationBarStyle.nightMode == MODE_NIGHT_NO)
   ```

   而 `enableEdgeToEdge()` 默认的导航栏样式是 `SystemBarStyle.auto(浅遮罩, 深遮罩)`，
   其 `nightMode` 是 `MODE_NIGHT_AUTO`（= 0）→ 这句被设成 **true**：
   **系统获准往导航栏后面加一层半透明遮罩**。手势导航下那正是"底部跟界面对不上"的
   那条带子（也就是金标联盟「导航条适配」说的割裂感）。官方文档也明说：要一个透明的
   手势导航栏，就把 `isNavigationBarContrastEnforced` 设成 false。

**修法**（`ui/theme/SystemBars.kt`，新增）：两个系统栏的样式都显式写成透明、
`detectDarkMode` 换成 **App 的深浅**、再把上面那句兜底关掉；MIUI 额外画的
`navigationBarDividerColor` 也一并透明掉（API 28+）。

⚠️ **API 29 以下保留库自带的浅 / 深遮罩**：那时的三键导航键是画在导航栏底色上的，
全透明会让它在浅色页面里彻底消失（minSdk 26）。

⚠️ 只把系统栏变透明还不够，**内容必须真的铺到它后面**：各页面根容器本来就是
`fillMaxSize()` + 自己的底色，底部再按 `navigationBarsPadding()` 主动避让。三条缺一不可。

实测（系统保持浅色、App 主题切到深色）：窗口的 `vsysui` 由
`LAYOUT_STABLE LIGHT_STATUS_BAR LIGHT_NAVIGATION_BAR` 变成 `LAYOUT_STABLE`。

### 33.2 主题色：浅底**派生**，不手写

`AccentColor` 七个色相 × 浅/深两档（`Color.kt`）。深色那一档不是"把浅色调亮"随手来的：
同一个色相在近黑底上要够亮才顶得住对比度（原来的 `BrandBlue → BrandBlueDark` 就是
这么来的，七色沿用同一套处理）。

真正省事的是**派生**：选中态填充与用户气泡都不手写色值，而是

```kotlin
lerp(页面底色, 主色, 0.16f)   // 浅色；深色 0.22f
```

7 色 × 2 档 = 28 个手调颜色，既难保证它们跟主色"是同一个色相"，改一个还要跟着改一片。
按比例掺进去则整套自动跟着主色走。那两个比例是**照原来那版蓝色反推**的
（算出来与 `#E8EDFF` / `#243056` 基本重合），所以**默认观感不变**。

范围刻意收窄：只动品牌色那一族（主色 / 选中态浅底 / 用户气泡）。页面底色、正文颜色、
功能色（危险 / 警告）都不动 —— 换主题色不该把"有错误"这类语义色也换掉。

### 33.3 三处"被借错的语义"

这一版里最有价值的其实不是上面两条，而是三个**同一类**的坑：拿一个有明确语义的
属性去当"强调"用，平时不显眼，一换主题色就全露出来。

| 位置 | 借了什么 | 为什么是错的 | 现在 |
|---|---|---|---|
| 「压缩上下文」按钮 | `CapsuleButton(selected = true)` | `selected` 的语义是"这个选项当前是开着的"，而那个分支的前提恰恰是**还没压缩** —— 一直在假装"已经压过了" | 去掉，回归朴素样式 |
| 输入栏 ⚙ / ✧ | `tint = colors.processText`（灰）当"未激活" | 同一行里 `⊕` 是黑的，灰的那两个看着像**禁用** | 统一为 `onSurface`（黑）；激活态改为"淡底 + **同色描边** + 同色内容" |
| 主题色色块 | 水波纹 | 波纹形状 = **节点的裁剪形状**。外层为了给外溢的选中描边留空间而不能裁剪 → 波纹成了方块 | 点击单独拆一个 30dp 的**圆**节点 |

最后一条值得单独记：圆形按钮上的水波纹是方块，永远是同一个原因 —— 漏了
`.clip(shape)`。而这里又有额外约束：选中那圈描边**外溢到节点之外**，所以外层不能裁，
只能让一个专门的圆形点击层去吃点击。
