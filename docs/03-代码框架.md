### 2.2.1 三个必须知道的坑（已实测踩过）

**坑 1：AGP 9 内置 Kotlin，必须移除 `org.jetbrains.kotlin.android` 插件**

AGP 9.0 起内置 Kotlin 编译能力。若仍应用 `kotlin-android` 插件，构建直接失败：

```
The 'org.jetbrains.kotlin.android' plugin is no longer required for Kotlin support since AGP 9.0.
```

**正确做法**：模块级 `plugins {}` 中**移除** `kotlin.android`，
但 `kotlin.plugin.compose` 与 `kotlin.plugin.serialization` 这两个**编译器插件仍需保留**。

**坑 2：AGP 9.4.1 内置的 KGP 是 2.2.10，对 mikepenz 库太旧**

AGP 9.4.1 的运行时依赖里写死了 `kotlin-gradle-plugin:2.2.10`。
而 `mikepenz 0.45.0` 的 `kotlin-stdlib` 要求 `2.4.10`，
低版本 Kotlin 编译器**无法读取高版本元数据**，会直接编译失败。

**正确做法**（AGP 官方推荐）：在根 `build.gradle.kts` 用 `buildscript` classpath 抬高：

```kotlin
buildscript {
    repositories { google(); mavenCentral() }
    dependencies {
        classpath("org.jetbrains.kotlin:kotlin-gradle-plugin:2.4.10")
        classpath("com.google.devtools.ksp:symbol-processing-gradle-plugin:2.3.12")
    }
}
```

**坑 3：`compileSdk 36` 会失败，且 AGP 8 无法规避**

依赖的 AAR 元数据要求 `minCompileSdk=37`。曾尝试保留 AGP 8.13.1 并用
`android.suppressUnsupportedCompileSdk=37` 压警告——**无效**，
因为失败原因不是 compileSdk 版本本身，而是依赖硬性要求 `AGP ≥ 9.1.0`：

```
Dependency 'androidx.compose.ui:ui-android:1.12.1' requires Android Gradle plugin 9.1.0 or higher.
```

**坑 4：SDK 平台目录命名**

新版 SDK 平台包名带次版本号：安装的是 `platforms;android-37.0`，
目录为 `platforms/android-37.0`（`AndroidVersion.ApiLevel=37.0`）。
AGP 9 能正确识别，无需手工建 `android-37` 目录。

> **KSP 版本说明**：KSP 官方声明「2.3.0 起 KSP 与 Kotlin 版本解耦，
> 可配合 Kotlin 2.2.* 及更新版本」。KSP 2.3.10 changelog 明确包含对
> Kotlin 2.4.0 默认模块名与 AGP 9 内置 Kotlin 的兼容修复。
> KSP1 已废弃且**不兼容 Kotlin 2.3+ / AGP 9+**，本项目仅使用 KSP2。

### 3.2 依赖注入

各 Store），ViewModel 通过 `viewModelFactory` 构造注入。

## 8. 性能设计

| 策略 | 说明 |
|---|---|
| **单 Activity** | 无 Navigation 组件，Screen 用状态枚举切换 |
| **无 DI 框架** | 手写 `AppContainer`，构造注入 |
| **无 Retrofit** | OkHttp 原生 `Call` + 手写 SSE 行解析 |
| **流式两阶段渲染** | §6.2，核心策略 |
| **UI 更新节流** | 流式增量每 ~50ms 合并一次 snapshot 提交，避免每 token 重组 |
| **LazyColumn 优化** | 稳定 `key`（消息 id）+ `contentType`（user/assistant/process） |
| **智能自动滚动** | 仅在用户贴底时跟随；离开底部只显示「回到底部」按钮，不打断阅读 |
| **Room 写入节流** | §4.4，流中 1.5s checkpoint，结束终写 |
| **图标自绘** | 不引 `material-icons-extended`（该库可增加数 MB） |
| **Release 优化** | R8 minify + 资源压缩 + 资源混淆 |

## 30. 包名与版本

### 30.1 定名

| 项 | 值 |
|---|---|
| `namespace` / `applicationId` | **`com.simplechat.app`** |
| 版本 | **`0.9.0-beta`**（`versionCode = 1`） |
| debug 后缀 | `.debug`（`applicationIdSuffix`） |

改名时一并处理了：**73 个源文件**的包声明与 import、`proguard-rules.pro` 的
三条 `keep` 规则（都写着全限定名）、Room 的 **schema 导出目录**
（`app/schemas/<DB 类全限定名>/`，名字跟着包走）。源码树也从
`java/<旧包名>/` 挪到 `java/com/simplechat/app/`。

> 漏掉任何一处都不会编译不过 —— 而是**运行时**才炸（R8 把序列化器裁掉、
> schema 导出到错地方）。所以改完必须 `assembleRelease` + 单测各跑一遍。

### 30.2 ⚠️ 包名一改就是「另一个 App」

数据在 `/data/data/<applicationId>/` 下，所以改包名等于**全新安装**：
旧数据看不见、`allowBackup=false` 也救不回来。

**真机上正确的迁移路径**：

```
旧版：设置 → 数据管理 → 导出所有数据（JSON）
装新包 → 设置 → 数据管理 → 导入所有数据
```

**`API Key 跨 App 解不开`**：密文用 Keystore 加密，而 Keystore 的密钥
**按 UID 隔离** —— 换了包名就是换了 UID，旧密文必然解不开。
界面会显示"未配置"，需要重填。这是 §19.3 里设计好的失败路径
（`decrypt` 返回空串而不是抛异常），不是缺陷。

> 模拟器上做过一次手工迁移（直接拷库与 DataStore）验证数据本身没问题：
> **DB v4 一条没丢**。但那只是模拟器上有 root 的便利，
> 真实用户走导出/导入。

### 30.3 User-Agent 不再写死

```kotlin
val USER_AGENT: String = "SimpleChat/${BuildConfig.VERSION_NAME} (Android)"
```

原先写死 `"SimpleChat/1.0.0 (Android)"`。改版本号那天它就变成假的了 ——
而它恰恰是**服务端看到的客户端版本**，错了没人会发现。改成从 `BuildConfig` 取。
