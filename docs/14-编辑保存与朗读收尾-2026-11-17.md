# 编辑保存、提醒顺序、朗读收尾与消息操作栏

实现日期：2026-11-17。纳入 **v1.1.5 / versionCode 21**，发布说明见根目录 `RELEASE_NOTES_v1.1.5.md`。

本轮来自真机验收反馈，五件事：三处行为缺陷、两处对齐官方客户端的界面调整。

## 1. 「保存」不再创建新分支

**现象**：编辑 AI 回复后只点「保存」，消息数量没变但多出一组 `‹ 1/2 ›`；
如果编辑的是会话中段的一条，**下半段对话当场消失**。

**根因**：`editMessage()` 的两个出口共用 `repository.addActiveVariant()` ——
它按"新增版本"实现，新版本挂在原消息的父亲下、成为兄弟。树模型里"当前对话 =
从根沿 active 走到底"，新兄弟没有子树，路径就断在这里。用户要的是改文字，
得到的却是"切了一个新分支"。

**修法**：`resend = false` 走新的 `ChatRepository.editMessageInPlace()`，一条 `UPDATE`
换掉正文，分支数、版本号、下游全部不动；`resend = true`（「保存并发送」）保持原来的
"新增版本 + 继续生成"，旧分支连同子树仍然可切回。

**跨协议的一个坑**（这也是不能只改 `content` 的原因）：

| 通道 | 界面渲染正文 | 请求里的正文 |
|---|---|---|
| OpenAI 兼容 | `UiMessage.content` | `MessageContent.text(content)` |
| Anthropic 兼容 | `timeline` 里的 `Text` 块 | `assistantContent(timeline)` |

只改 `content` 会得到"OpenAI 那边生效、扩展通道那边半点没变"。所以新增纯函数
`rewriteTimelineText()`：把时间线里的正文块合并成一段新文本并放回第一块正文的位置，
思考 / 搜索 / 读链接块原序保留（它们描述的是这段答案的来历，不该被错别字修改抹掉）。

## 2. 「保存并发送」的 400：`latest_reminder` 必须紧跟 `user`

**真机报错原文**：

```
messages.9: a `latest_reminder` message must be immediately followed by a `user` message
(request_id: 7e70a6aa-…)
```

**根因**：时间地点提醒原先插在"路径最后一条之前"。只要最后一条是 assistant 就踩线，
而「编辑 AI 回复 → 保存并发送」正是这个形状：新回复还在流式、被 `orderedOutgoingMessages`
滤掉，路径以**被编辑的那条 assistant** 结尾 —— 于是提醒后面跟的是 assistant。

**修法**：

- 提醒改为插在**最后一条 `user`** 之前（没有任何形状能绕过这条约束；一条 user 都没有
  就不发提醒，少一条时间信息远好过整轮 400）；
- `sanitizeTurns()` 再兜一层：合并 / 丢空消息之后落单的提醒（后面不是 user）直接丢弃。

**与端点无关**：OpenAI 通道没有提醒角色，这段逻辑只在扩展通道生效；两条通道的
请求装配本来就是两套（`buildRequestMessages` / `buildAnthropicRequest`），
本轮没有把任何一方的形状套到另一方上。

## 3. 朗读被截断最后几个字

**现象**：点朗读，正文念到最后一个自然段末尾会少三四个字。

**根因**：`AudioTrack.write` 返回只代表"数据进了缓冲"，不代表"已经播出来"。
播放缓冲是 1 秒（24 kHz × 2 B = 48000 字节），而 `speakOfficial()` 的收尾
立刻 `pause()` + `flush()` + `release()` —— `flush()` 把还没播的尾巴整段丢掉。
一句话末尾一秒 ≈ 三四个汉字，与反馈完全对上。

**修法**：写完不立即收尾，先 `gate.finish()` 再 `awaitPlaybackEnd()`：轮询
`playbackHeadPosition`（已播帧数）直到追上"已交给轨道的帧数"（`PcmWriter.bytesWritten / 2`），
最多等"剩余时长 + 1 秒"。用户点停止时立即返回，不拖泥带水。

判据抽成两个纯函数 `pendingPlaybackFrames()` / `drainBudgetMs()`，单测钉死。

## 4. 消息操作栏：新增「选择文本」，刷新按钮右置

对齐官方客户端的消息动作布局：

- 长按菜单在「复制」下方新增 **选择文本**：进入选择态后该条正文包一层 Compose
  `SelectionContainer`（长按起选、拖动拉选区、系统工具栏复制 / 全选），下方出现
  「拖动选择文字 · 完成」提示条；这期间整行的点击 / 长按让给选区。
  平时**不**常驻 `SelectionContainer` —— 那样长按会被选区抢走，而长按是本条的菜单入口。
- 操作栏里 **重新生成** 移到**行尾最右**，其余（复制 / 续写 / 朗读 / 编辑 / 删除）
  靠左；模型名 · token 数占用中间的弹性空白，因此刷新按钮不会随元信息出现而左右横跳。

## 5. 菜单与输入栏的投影

- 所有弹出菜单共用 `AppMenu` 一处实现，因此一处改动覆盖全应用：**双层投影**
  （16dp 宽投影给氛围 + 3dp 窄投影收边界）、菜单项行高 44 → 46dp、
  阴影预留空间 26 → 30dp。
- 输入栏与输入面板同样换成双层投影（贴边层为宽层的 1/4，随展开动画一起淡出）。
- 新增 `Modifier.layeredShadow()`：单层 `shadow` 只有一种扩散，要么边缘发虚、
  要么没有距离感；两层叠加才既"落地"又"浮起"。

## 6. 设置项

隐藏「设置 → 图片跳过提醒」开关（`settings_image_skip_notice`）。跳过提示本身仍会出现，
横幅上的「不再提醒」仍然写入同一个偏好；只是不再提供一个可见的恢复入口 ——
需要恢复时改回这一行即可。

## 剩余风险

- 选择文本依赖 Compose 的 `SelectionContainer`：Mermaid 图与代码高亮块内部的选区由
  各自的渲染实现决定，跨组件的选择范围可能不连续（正文纯文本不受影响）。
- 「保存并发送」在 OpenAI 通道上的形状是"末尾一条 assistant"（等于让模型接着写）。
  部分要求"最后一条必须是 user"的第三方网关可能仍然拒绝 —— 那是该网关的额外约束，
  与扩展通道的 400 不是同一件事；遇到时按网关报错单独处理。
