# 17 · 文本选择交互要求

状态：历史需求记录。当前实现和验证结果见 [文本选择交互修复](18-选择文本交互-修复记录.md)。

## 目标

在消息原按下位置进入文本选择。滚动期间保留选区，轻点退出时避免触发其他消息操作。

## 交互要求

| 操作 | 预期结果 |
|---|---|
| 长按消息后选择“选择文本” | 在原按下位置选中单词，显示原生手柄和文本工具栏 |
| 轻点消息、顶栏或留白 | 退出选择，当前触摸不触发消息点击或菜单 |
| 纵向滚动并返回原位置 | 选择状态和已选范围保持 |
| 长按或拖动手柄 | 扩展选区，使用原生复制操作 |
| 退出后再次长按 | 正常显示消息菜单 |
| 其他回复继续生成 | 已选消息保持可操作，不触发全列表重绘 |
| 选择代码、表格和正文 | 按显示顺序复制可选择文本 |
| 选择分页消息 | 保留当前页和代码块展开状态 |

## 实现范围

- 消息正文使用 Jetpack Compose 和原生 `SelectionContainer`。
- 选择态由屏幕级状态协调，选区由原生 `SelectionState` 保存。
- 图片和 Canvas 公式不参与文本选择。
- 正在生成的消息继续使用既有菜单准入规则。
- 当前页未渲染的其他分页内容不属于原生“全选”范围。

## 验收

1. 在按下位置进入选择，并验证手柄与复制工具栏。
2. 慢速拖动、惯性滚动及完整离屏后返回，确认原选区保持。
3. 跨段落、代码和表格复制，核对内容顺序。
4. 轻点退出，确认没有触发下方控件。
5. 在长用户消息、非首页分页内容和其他回复更新时重复验证。
6. 按 Android 版本分别记录结果。已验证版本的结果不代表所有受支持版本。

测试入口为 `TextSelectionRegression`。设备范围、测试结果及已知限制见实现记录和本轮发布验收记录。
