# 消息删除、分支保留与切换闪屏修复方案

交付日期 2026-11-23。本文是供 Android 开发和测试执行的规格。下文所有验收项均待实施后验证。

## 1. 用户最终看到什么

**一次删除将所选消息的所有版本移入回收站。每个版本后面仍有内容的分支留在原会话，可读、可切换、可续写。**

假设用户把同一个提问编辑重发三次。当前正在看 B。删除这条提问后应得到下表结果。

| 切换位置 | 删除前 | 删除后 |
|---|---|---|
| A | 提问 A → 回答 A → 追问 A | 回答 A → 追问 A |
| B（当前） | 提问 B → 回答 B → 追问 B | 仍显示回答 B → 追问 B |
| C | 提问 C → 回答 C → 追问 C | 回答 C → 追问 C |

点击 B 的切换按钮能看到 A、C 各自的整条后续。重启后仍打开上次选择的分支。另一种情况是同一条时间线上依次发了三个独立提问，此时删第二个提问只清除第二个提问的版本，连它收到的回答也要保留。

| 入口 | 界面与行为 |
|---|---|
| 消息菜单 → 分享 | 保留原有分享入口与分享多选界面。 |
| 消息菜单 → 删除 | 一次确认，按钮为「取消」「移入回收站」，范围固定为这条消息的所有版本。 |
| 消息菜单 → 多选并删除 | 排在「删除」下方。复用选择组件，底栏为「取消」和红底「删除（N）」。「N」为选中的逻辑消息数，零项禁用。确认前可随时退出。 |
| 已删除位置 | 有多条可选后续时，在原位置显示一行紧凑的「消息已删除　‹ 分支 2/3 ›」。分叉位置只有一个可选项时直通该后续，叶子直接消失。多层分叉各保留能通往其他后续的选择器。 |

如果选区复用分享界面的一问一答分组，**删除的勾选单位仍须是单条消息**。勾选用户消息不能顺带删除其回答。已删除位置仅支持分支导航和无障碍读出分支编号。

单删确认文案为「将这条消息的所有版本移入回收站。后续消息和分支会留在原会话。你可以在回收站恢复这些版本。」选中 AI 回复时另起一行「如果不满意这条回复，请使用『编辑』或『重新生成』功能。」批量改为「将所选 N 条消息的所有版本移入回收站。其他消息和分支会留在原会话。」英文单删使用 “Move all versions of this message to the Recycle Bin? Later messages and branches will stay in the conversation. You can restore these versions from the Recycle Bin.” 和 “To change this reply, use Edit or Regenerate.” 批量文案使用中英文数量资源。移入成功后提示「已移入回收站」。

### 回收站页面

- 复用现有回收站入口、标题栏和列表样式。页面顶部提供「会话」「消息」两个可点标签，内容区支持左右滑动切换。默认打开「会话」，各页独立记住滚动位置、加载状态和空状态。标签支持无障碍读取、焦点和点击，纵向滚动优先由各页列表消费。
- 「会话」保留现有列表。「消息」按删除时间倒序，每条记录对应一条逻辑消息及其被删除的所有版本。批删选了三个消息组，就出现三个可独立恢复的条目。条目展示所属会话、角色、短预览或附件提示、版本数和删除时间。每条提供「恢复所有版本」和「彻底删除」，预览按需读取，附件只在预览需要时加载。
- 在「消息」页把所有版本恢复到原会话、原位置及原分支。若用户已切换分支或继续聊天，保留当前仍有效的选择及新增后续。可在恢复成功提示里提供「查看会话」，由用户决定何时跳转。
- 「彻底删除」和页面底部的清空操作使用危险样式和确认。当前页清空明确命名为「清空已删除消息」或「清空已删除会话」，确认时复核同一批记录的 ID。单条彻底删除文案为「将彻底删除这条消息的所有版本。后续消息和分支会留在原会话。此操作不可撤销。」会话彻底删除或清空会话的确认提示说明，所属消息回收站条目也会一起清除。
- 本方案按消息条目长期保留设计，由用户主动彻底删除或清空消息。整段会话继续执行现有 15 天清理规则，会话彻底删除时一并清理其消息回收站记录。会话进入回收站期间，所属消息条目在「消息」页暂时隐藏，在「会话」页显示其数量。先恢复会话，再独立决定是否恢复里面已删的消息。

## 3. 移入回收站、恢复与彻底删除

1. **迁移与状态。** 在 Room 16 上做显式迁移（如版本已前移则顺延）。消息增加 `trashedAt`、用于聚合单次操作的 `trashOperationId`、永久删除结构标志 `isDeletedNode`。`trashedAt != null` 的行仍持有原 payload，永久结构行只保存树字段，正常内容行两种标记均为空或默认。补齐 `MessageLight`、显式投影与 Room schema。旧行默认可见，合法空正文、附件消息和失败消息按正常消息处理。
2. **移入。** 单删与批删共用事务。在同一会话内，根据 `versionGroup ?: parentId` 展开所选逻辑组的全部可见版本并去重。一次操作共用时间和操作 ID，回收站用 `(conversationId, trashOperationId, groupKey)` 聚合和执行。这样新编辑重发形成的有效版本和日后删除批次都能独立识别。跨会话 ID、过期选择、重复确认均复核，每次操作只处理本次明确的成员。保持每行 ID、父链、原顺序和附件引用。
3. **可达性和选择。** 用轻量骨架自底向上计算能否通往正常消息，包含非活跃子树。能通往有效后续的回收站行或永久结构行继续参与导航。只包含回收站内容的选项暂时从会话隐藏。当前分支仍有后续时保留有效 active，原选项不可达时按原顺序选下一存活兄弟，再选上一项，否则回到最近的合法位置。保留未访问分支内部仍有效的选择。删除最后一条时显示正常空会话，下次新消息可从根写入。损坏数据导致无法判明归属时回滚。
4. **恢复。** 在事务中复核条目与所属会话状态，清除该条目的回收站字段，再计算可达性和 active。保留当前有效的分叉选择和新写入消息，仅在分叉没有有效选项时选择恢复的分支，按原顺序确定兜底。若恢复目标的父消息还在另一个回收站条目中，父节点继续承载导航，恢复出的子消息可以访问。逐次验证先恢复父、先恢复子，以及整段隐藏后已有新根消息的情况。恢复不复制行，不合并分支。
5. **彻底删除。** 同一事务删除该条目的负载。只要节点还有正常后代或可恢复后代，就清除正文、附件引用、推理、时间线、错误、模型统计、图片请求等负载，并转为永久结构行，保留 ID、父 ID、组和顺序。底向上清理不能通往任何正常或可恢复消息的永久结构行。会话彻底删除时清理该会话全部三类消息、附件引用和相关元数据。附件回收在事务提交后进行，核对其他有效消息、回收站条目、分叉会话和草稿的引用后再删文件。
6. **缓存与并发。** 移入回收站时使覆盖该内容的所有分支摘要失效，按修改前祖先链判断。压缩 checkpoint 和有来源关联的记忆或导出缓存同时失效。恢复后按当前有效历史重新生成摘要。删除、恢复、彻底删除与发送等同会话写操作串行，所属会话状态在事务内复核。回收站恢复与清理竞态按先提交的事务处理，界面以数据库结果为准。
7. **升级。** 旧 build 已重挂的历史数据以库里现存父链为准。`versionGroup` 用于识别历史版本组。迁移保住升级前仍可访问的每条分支，恢复功能适用于升级后进入回收站的记录。

## 4. 显示、上下文与备份

分支选择器的候选是同父节点下所有可达选项，包括其他历史版本组的真实消息和仍有有效后续的隐藏节点。删除范围仍按逻辑版本组计算。选择器按节点 ID 激活，位置编号仅用于显示。即使一个结构节点只有一个孩子，只要它还有同父的可达兄弟，进入它时也须保留同层选择器。

从同一条结构路径生成两种结果。显示层得到可见消息及必要的分支导航行。请求层只得到当前路径的有效消息。树遍历保留通向有效后续的隐藏节点。正文和附件仅由回收站的权限范围内查询读取，聊天路径查询直接投影成无负载的导航行。`loadActivePath` 的轻量读和大行回退 `loadActivePathFull` 须产出相同结果。

- 新增消息根据当前分支的实际写入位置选择父 ID。编辑、重生成和「从这里新建对话」分别验证归属。复制为独立会话只复制选定路径的有效内容，重建其新父链。分享、朗读、搜索结果、会话预览、Markdown 导出、跨对话记忆及附件发送跳过回收站内容和永久结构行。导航行不计入选择数量、消息数或 token。
- 普通导出和默认备份排除回收站消息的负载及仅供恢复的分支。自有备份在有效后续仍依赖隐藏父节点时写入无负载的结构行，保留可达父链、组和选中状态。完整备份界面说明消息回收站内容的排除范围，并验证流式与普通导入导出一致。用户此前保存的副本仍可按原方式导入。
- `RequestOrdering.kt` 目前会略过流式/真正空的行，保留纯附件用户消息，并从第一条真实 user 开始构造历史。本期保留这条起始规则。例：删掉根提问，界面仍显示「旧回答 → 新追问」，下一次请求从「新追问」开始。禁止为了携带旧回答虚构提问。删除中间消息造成相邻同角色时保持原角色和顺序，由协议构造层按其格式表示，必要时合并为有边界的同角色内容块。对附件、思考和工具块沿用各协议输出约束，完整调用/结果配对才可回放。
- 覆盖仓库 `ApiStyle` 的三条实际路径 `OPENAI`、`OPENAI_RESPONSES`、`ANTHROPIC`。用录制请求或 mock 服务断言具体 JSON、角色序列、附件与工具关联，覆盖自动协议选择、切换模型后续写、删除前有压缩摘要、纯附件开头。检查发送、重试和压缩入口均采用相同过滤规则。测试通过的证据是实际构造的请求体和可解析的响应。

## 5. 切换分支闪屏与阅读位置

**视觉目标：用户在屏幕中部点「›」，下一帧能看到的变化应当只有分支内容和编号。按钮保持在手指下面。** 删除时优先让原先能看见的第一条存活后续保持在原高度。

1. **复现并记录。** 在同一会话建短 A、带多屏 Markdown/代码块或图片的长 B，以及短 C，每条接不同数量后续。将按钮滚到屏幕中部，依次点 A→B→A、B→C，短间隔连续点击。逐帧录屏，同时记单调帧时间、会话 ID、路径修订号、可见 key、按钮中心 Y、首项 offset、透明度及本帧的滚动发起方。分别识别空列表、整屏淡出、错误的首帧落点、媒体晚到导致的二次位移。
2. **点击时就取锚。** 在启动异步数据库动作前，记录分支按钮中心在列表视口中的 Y、分叉父节点、目标子节点 ID、会话与操作序号。删除或批删则记录可见候选的 ID、边缘与 Y，优先向下找存活消息，再找上一条，再取最近合法位置。取消确认无需启动定位。会话切换或用户主动拖动时取消旧定位。
3. **一次发布。** 准备新路径时保持旧画面，保留同一 `LazyListState`。在一次 Compose 可观察状态提交中发布新行、修订号和目标锚点，可沿用流式写入所依赖的列表并用一次可变快照提交。导航行用所在会话和分叉位置的稳定 key，普通行沿用消息 ID，行内折叠与文本选择按真实消息 ID 隔离。切分支不得触发换会话的 `dissolve`、加载屏或列表整体入场动画。
4. **新路径首次可见布局直接落位。** 对已知行内锚点，按同一坐标系把目标按钮中心还原到旧 Y，调用带目标 offset 的定位，而非先按默认 offset 滚到行首。若目标行首次出现、行高未知，优先让导航控件成为独立、稳定、可直接定位的列表项，使定位不依赖整条回复的测量高度。若现有行布局必须保留，则在相同宽度和字体约束下预量目标锚点并保持旧画面，直到能显示已对齐的新路径。验证顶部 padding、输入栏、系统 inset 与列表首尾的可用滚动范围；边界允许夹到最近可达位置。避免用固定延时、整屏透明或连续数帧可见滚动掩盖中间态。
5. **同一时刻一个滚动来源。** 路径定位期间暂停自动跟底、`messages.size` 驱动的追加滚动、搜索定位和无关动画。定位提交后继续用户的阅读状态，主动回到底部或发消息才恢复相应跟随。图片或 Markdown 的延迟测量优先预留尺寸；若仍改变锚点，在布局阶段补偿一次实际变化，用户开始拖动即让位。短分支不可达时可保留有界临时间距，回到底部或主动滚动后释放，连续切换不能累计空白。
6. **并发与失败。** 同一分叉的连续点击按最后有效目标处理。目标应从待切分支的逻辑位置推导，避免连点两次都读旧 `2/3`。串行提交数据库 active 和对应 UI 修订，旧结果不能覆盖新结果或新会话。数据库失败保留原路径、解除临时滚动限制；持久化成功但读取失败则重新读取真实 active 后再允许下一次切换。

## 6. 验收矩阵与交付顺序

| 场景 | 必须拿到的证据 |
|---|---|
| 三版本各有两级后续，从 B 删除 | 三个提问版本只在同一个回收站条目中可见。六条后续父 ID 和正文逐条一致，界面停 B，A/B/C 可来回切。各分支分别续写，强杀重开再核对。恢复时保留续写结果。 |
| 时间线中间、根、尾、仅一条、全部选中 | 存活消息仍可读可续写；尾部及空会话没有空导航行；重新进入落在正确分支。 |
| A/C 有后续，B 为空且活跃；某一后续再分两层 | B 移入回收站后稳定落到 C，编号重算。嵌套分支能独立切，连续删除两层空分叉不残留。 |
| 批量选父子、隔项、重复版本组；混合用户和 AI | 事务按组去重，数量正确，取消零改动；未勾选回答和非活跃分支原样存在。模拟事务失败、重复确认。 |
| v16 数据库、旧备份、已提升的异组同父节点、共用附件 | 迁移前后对照 ID、组、父链、active。删一组仍能访问另一组。新备份往返恢复有效树结构，备份中查不到回收站负载，共用附件可打开。 |
| 三协议、纯附件、相邻同角色、开头是回答、工具调用、已有摘要 | 捕获最终请求并断言只含有效活跃历史。搜索、记忆、分享、导出均找不到已删测试串。 |
| 回收站双页、批删、恢复、彻底删除 | 横滑和点标签同步，两个列表保留各自滚动位置。批删条目可独立恢复，重启仍可见。彻底删除后旧正文及附件引用释放，仍存活的后续和共用附件可用。清空确认应显示准确范围。 |
