# 22 · 上下文压缩与恢复

日期：2026 年 11 月 18 日。适用版本：v1.1.6 预发布，构建号 28。

本次修复让超长对话按批处理服务端输入限制，并在失败后恢复已完成的工作。
压缩时只显示加载动画和停止入口，完整摘要在成功后显示。本地消息不删除、不改写。

## 问题与范围

用户反馈：约 749k 的对话压缩失败，服务端返回 `32942 tokens exceeds max 32768 tokens`。
客户端配置的模型上下文为 1M，不能据此将模型能力改为 32K。

旧实现将每批最多 48,000 个字符拼成一条 user 消息，只根据模型总窗口规划请求。
如果服务端对当前请求另有限制，或分词估算存在偏差，压缩会直接终止。
HTTP 错误已转换为用户提示，压缩层再次转换，造成嵌套重复文案。

DeepSeek 官方文档列出 1M 上下文，并说明 Anthropic 兼容协议可附加搜索、读链接及输入输出审查。
本次未取得真实失败请求的服务端追踪结果，不能确认 32K 校验来自哪一项处理。
修复保留当前模型与协议，不因一次拒绝改写模型能力，也不移除输入输出审查。

## 压缩策略

1. 固定当前源路径、模型、接口、协议、认证配置和压缩提示词，生成内容指纹。
2. 通常保留最近 6 条完整消息。近期内容超过模型窗口一半时，按用户轮次缩小保留范围，至少保留最新一轮。
3. 按顺序分块处理旧消息、文本附件及已有摘要。单条超长消息可拆分，Unicode 代理对保持完整。
4. 独立生成每批摘要，再按时间顺序分层合并。避免每收到一批原文就重新改写全部早期摘要。
5. 只在完整响应通过校验后推进源偏移并保存进度。半成品、空输出和截断输出均不推进偏移。
6. 全部完成后检查会话、路径修订号和原摘要是否仍匹配，再一次替换正式摘要并删除进度文件。

摘要按需要保留当前目标、用户限制、确认事实、关键名称与数值、工作进度、未决问题及创作设定。
历史指令只作为资料处理；压缩请求不配置搜索和读链接工具。最近消息继续以完整内容发送。

## 预算与恢复

| 项目 | 行为 |
|---|---|
| 初始分块 | 最多 48,000 个 UTF-16 字符；同时受 token 预算限制 |
| 估算余量 | 文本估算乘以 1.5；仅使用请求窗口的 75%，再扣除系统提示、128 token 开销和输出预算 |
| 输出预算 | 原文批次最多 2,048 token，合并批次最多 4,096 token；小窗口按比例缩小 |
| 输入超限或 HTTP 413 | 将当前批次大小至少减半；若错误包含输入上限，仅在本次压缩采用该上限；最多调整 8 次 |
| 网络中断、429、临时服务故障、空输出 | 当前批次最多重试 2 次，等待 600 ms、2,400 ms；网络层自身的有限重试仍适用 |
| 输出截断 | 优先增加输出预算，最多 8,192 token；仍不足时缩小输入；最多调整 4 次 |
| 请求等待 | 每次摘要尝试最多 180 秒，超时按临时故障处理 |
| 鉴权、额度、模型或通道配置错误 | 直接提示，不反复缩批 |
| 无法收敛 | 摘要总长度未减少或超过 12 次合并层级时停止，保留原摘要 |

这些限制控制单次压缩的工作量，不修改模型列表、输入栏的 1M 窗口或正常聊天请求的配置。
请求长度的本地估算不等同于服务端分词结果；服务端拒绝仍需自适应恢复。

## 进度与数据保护

- 进度位于应用私有、排除系统备份的目录。文件只保存指纹、源偏移、已完成摘要及批次预算，不保存 API Key 或整份源对话。
- 每个会话最多保留一份进度。先同步临时文件，再原子替换，避免中断留下半份 JSON。
- 源内容、模型、接口、协议、认证配置或提示词变化后，旧指纹不匹配，重新开始。
- 损坏或过大的进度文件不复用。存储失败不使已完成的模型响应失效，但该部分工作可能需要重做。
- 成功完成、放弃正式摘要或删除会话时清理相应进度；删除全部会话时清理全部进度。
- 取消或关闭应用后不会自动发起新请求。用户再次选择压缩时恢复匹配的已保存进度。
- 运行日志只记录层级、批次、已处理字符数和恢复类型，不输出对话正文或凭据。

## 文件 API 衔接

文件引用减少重复上传和请求体组装，文件内容被模型读取后仍会占用上下文。
压缩读取本地消息正文及文本附件，不重新上传已保留的长文本。

仅有远程 `file_id`、没有可读取文本的附件不能视为空文件。若这种附件位于待压缩范围内，
压缩会在发起摘要请求前提示补充正文，并保留原摘要和所有消息。
文件 API 需保留可供压缩读取的文本，或提供文本提取能力，才能压缩这部分内容。

## 验证

专项单元测试覆盖百万级中文及 emoji 输入、32K 请求拒绝、未知输入限制、完整原文覆盖、分层合并、
断流与取消、重试上限、空摘要与截断、鉴权错误、进度恢复、损坏文件及内容指纹变更。

设备验证使用生产 ViewModel、HTTP/SSE 客户端、Room 和 Compose 组件，服务端响应由本地拦截器提供。
真实服务端对该请求返回 32K 限制的原因、模型摘要质量和实际耗时仍需使用用户会话复测。
自动测试不等同于语义无损，也不能据此宣称与某一 harness 的全部能力相同。

|---|---|
| 单元测试 | 677 项，667 项通过，10 项因缺少外部备份资料跳过，0 项失败 |
| 收敛失败后的再次尝试 | 补充修正后运行 25 项压缩专项测试，全部通过；仅重做未收敛的当前层 |
| Android Lint | 0 个错误、94 个警告、7 条提示 |
| 构建与签名 | Debug、设备测试包和 R8 Release 构建通过；正式签名校验通过 |
| Android 10 / API 29 | OpenAI 和 Anthropic 两种协议均通过生产 ViewModel、HTTP/SSE、Room 及 Compose 联动验证 |

| 进度恢复 | 已完成一批后取消并重建 ViewModel；从私有进度文件继续，不重做已完成的原文批次 |
| 数据保护 | 取消时原摘要保持；成功后覆盖正确的消息边界，完整本地原文保持不变，进度文件已清理 |

测试使用以已发布源码为基础、只包含本次压缩改动的独立快照。共享目录中的文件 API 功能由另一任务同时开发，
其整体实现与实际服务端联动不在上述通过结论内。自动测试没有向真实服务端上传会话或使用真实 Key。

## 实机检查

1. 打开此前无法压缩的长对话，开始压缩。确认仅显示加载状态，界面仍可响应操作。
2. 中途停止后重新压缩，确认能继续完成；原消息数量和附件不变。
3. 完成后检查摘要中的关键人物、关系、限制、决定及未完成事项。
4. 继续发送一条消息，确认新回复可利用摘要及最近完整对话。
5. 修改待压缩原文或切换模型后重试，确认使用当前内容和配置。
