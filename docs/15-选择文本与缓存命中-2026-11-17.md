# 选择文本、首字过渡、操作栏与缓存命中

实现日期：2026-11-17。v1.1.5 / versionCode 22 的真机反馈第二轮，接在
[`14-编辑保存与朗读收尾-2026-11-17.md`](14-编辑保存与朗读收尾-2026-11-17.md) 之后。

## 1. 选择文本：不要"模式"，点哪里就从哪里开始选

上一版的做法是"进入选择态 → 界面出现一条提示和「完成」按钮 → 自己再长按起选"。
用户不接受那个中间态：它多了一个按钮、多了一次手动长按。

现在：

- 菜单里点「选择文本」后**没有任何界面元素**出现；
- 选区**立刻**落在刚才长按的位置上（词/片段级别），可以直接拖动拉长、系统工具栏复制；
- **点空白处即退出**（列表空白、其他消息、输入栏都算），不设「完成」按钮。

实现要点（`MessageList.kt`）：

| 问题 | 做法 |
|---|---|
| 怎么"从按下的位置开始选" | Compose 没有"按坐标设置选区"的公开接口（`SelectionState` 只认全局字符偏移，多段文本还要自己累计算长）。改为在同一个点上**合成一次长按**（`startSelectionAt`）：命中测试、行定位、手柄全走系统原本那一条路 |
| 合成的长按会不会被当成"点了一下" | 按住 560ms（> 系统长按阈值 500ms）；同时列表层的"点空白退出"检测带一个空的 `onLongPress`，长按被它消费掉，不会再触发 `onTap` |
| 什么时候注入 | 等两帧 + 90ms：`SelectionContainer` 要挂上去、菜单要收起 |
| 怎么退出 | `selectingId` 抬到列表层，`dismissSelectionOnTap` 挂在 `LazyColumn` 上。**只有"点一下"才退出** —— 滚动不退出：选到一半往上翻一屏看上文是常规操作，一滚就丢选区等于把"选完再复制"堵死 |

风险：注入的是本进程内的合成事件，只在真机上验证得准。若某台设备上没生效，
表现只是"进入选择态但没自动选中"，用户仍可长按起选 —— 不崩、不卡。

## 2. 操作栏：刷新键**永远**在行尾

上一版把权重挂在 `AnimatedVisibility` 上：不显示模型信息时它不占位，
刷新键就滑回按钮旁边，表现为"只有显示模型时才居右"。

改为：`Box(Modifier.weight(1f))` 恒定占住中间剩余宽度，元信息（`MessageMetaSlot`）
作为它的内容淡入淡出，刷新键固定跟在 Box 之后 —— 位置与元信息是否可见无关。

## 3. 首 token 等待：「加载中…」过渡

请求发出到第一个 token 之间，界面上原先什么都没有。长上下文 + 思考型模型这一段
可以走十几秒，看起来像"消息没发出去"。

新增 `WaitingIndicator`（`ThinkingHeader.kt`）：一个 15dp 的旋转弧 + 「加载中」，
省略号按秒循环。形状、色值、左缘对齐都与思考栏一致 —— 第一个思考块到达时，
视觉上是同一行在换字，而不是凭空冒出一个控件。

判据：`streaming && 正文空 && 没有思考 && 没有时间线`。任何一块内容出现即让位。

## 4. 缓存命中率

**能拿到。** 两条通道在流里都会回用量，而且客户端本来就已经解析出来了
（`StreamEvent.Usage`），只是此前被丢掉：

| 通道 | 字段 | 含义 |
|---|---|---|
| DeepSeek（OpenAI 兼容） | `usage.prompt_cache_hit_tokens` | 命中前缀缓存的输入 token |
| Anthropic 兼容 | `message_start.usage.cache_read_input_tokens` | 命中缓存的输入 token（`cache_creation_input_tokens` 是写入侧，计入输入总数） |

现在的做法：

- `ChatViewModel.recordUsage()` 收下并**合并**两段上报（Anthropic 的输入侧在
  `message_start`、输出侧在 `message_delta`；缺字段不能把已有值冲成 0）；
- 只保留**最近一次**请求（`lastUsage`）—— 缓存命中率是"这一轮前缀有没有被复用"，
  跨轮平均会把它稀释成一个看不出变化的数字；切换会话时清空；
- 「上下文占用」面板的统计区新增一行 **缓存命中（最近一次）· 命中/输入 · 百分比**；
  服务端没报缓存字段时整行不出现，不显示假的 0%。

若要**跨轮聚合**（整条会话平均命中率），需要给 `messages` 加两列并做一次数据库迁移；
当前版本没做，先把"最近一次"这个最有信息量的数字摆出来。

## 5. API Key 的字符集校验

真机报错：

```text
Unexpected char 0x4f55 at 8 in Authorization value
```

`0x4f55` 是「何」—— Key 里混进了中文。OkHttp 只会把**第一个非法字符的码点**丢出来，
既不说是哪个字段，也不说该改什么；而 HTTP 头只接受可见 ASCII（0x21–0x7E），
粘贴带进来的换行、全角标点、中文占位符全会踩这一条。

三处一起收口：

| 位置 | 做法 |
|---|---|
| 保存入口（`SettingsStore.setApiKey`） | 先 `ApiKey.normalize()` 去掉**所有空白**（换行是最常见的一种） |
| 设置对话框 | 非 ASCII 当场拦下：红字写明检测到的码点，不关窗、不保存，改一个字就能再存 |
| 请求之前（`ChatViewModel.startStream`） | 旧配置 / 导入配置里的坏 Key 也拦得住：这条回复直接标成错误并说清去哪儿改，不会留下一个空转的流式气泡 |
| 异常兜底（`Throwable.userMessage()`） | 已经发出去才发现时，`IllegalArgumentException` 里的 `Authorization` 文案翻成同一句人话 |

朗读的官方通道同样加了这个判断（`SpeechOutput.speakOfficial`）。纯逻辑在 `data/ApiKey.kt`，
`ApiKeyTest` 5 项：空白清洗、合法字符、中文、全角标点与换行、空 Key。

## 6. 开源许可与版权

「关于」页原先是一串 `名字 (MIT)` 便签：没有版本、没有版权方、没有链接、没有许可证全文。
合规要求每个组件能回答五件事，因此新增**二级页「开源许可」**（`关于 → 开源许可`）：

| 字段 | 内容 |
|---|---|
| 名称 | 组件名 |
| 版本 | 与 `gradle/libs.versions.toml` 对齐（BOM 管理的写 BOM 版本） |
| 许可证 | SPDX 标识（Apache-2.0 / MIT / ISC） |
| 版权所有 | 按上游 LICENSE 的写法 |
| 项目主页 / 许可证全文 | 两条可点链接：项目 URL + 官方许可证文本（apache.org / opensource.org / spdx.org） |

许可证正文**不随包复制**：几千字的法律文本抄错一个字就是错文本，指向官方地址永远是对的。
清单只收**随包分发**的组件（JUnit 只在测试期存在，不列）。

另有「参考实现」一栏，只写 DeepSeek Chat Demo（MIT）—— 且写明**参考的是聊天记录导入
的归档格式与流程**，代码未随包分发；Simple-Agent 已按要求去掉。

## 8. 后台继续生成（默认行为，不是开关）

回复生成活在 `ChatViewModel.viewModelScope` 的协程里。应用一退到后台，进程就是普通
后台进程：系统随时能回收，熄屏几分钟后更容易被判定为空闲 —— 表现是**长回复写到一半
突然停住**（落库为 STOPPED），用户回来只看到半截。

做法：生成期间起一个 `dataSync` 型**前台服务**（`service/GenerationService`），
把进程提到"用户可感知"的优先级；Doze 的网络限制也不作用于前台服务。
同时持有一个 `PARTIAL_WAKE_LOCK`（熄屏时保住 CPU，不点亮屏幕），生成结束立刻释放。

| 时机 | 动作 |
|---|---|
| `startStream` 把 `isStreaming` 置真 | `BackgroundGeneration.sync(true)` → `startForegroundService` |
| 流结束（正常 / 出错 / 被新流顶掉） | `sync(false)` → `stopService`，通知一起撤掉 |
| 用户点停止 / ViewModel 回收 | `sync(false)` |

要点：

- **幂等**：`sync` 只在状态真的变化时才动服务，流的每次状态变化都可以放心调；
- 通知是前台服务的强制要求，**不能隐藏**；文案只有一行「正在生成回复」，
  结束即消失，不常驻；
- 权限只有 `FOREGROUND_SERVICE` / `FOREGROUND_SERVICE_DATA_SYNC` / `WAKE_LOCK`
  / `POST_NOTIFICATIONS`，都**不弹窗**（Android 13+ 未授予通知权限时服务照常运行，
  只是通知不显示）；
- 不 `START_STICKY`：进程被杀后重建一个空服务没有意义，只会留下假通知；
- 边界：**进程被系统杀掉**（内存压力）时仍然会丢 —— 那是另一个量级的工程
  （WorkManager + 断点续传），当前不做。

## 9. 检查更新

「关于」页新增一行**检查更新**（只有它可点，因此单独一张卡）。点一下查
`https://api.github.com/repos/Pokanshuu/Simple-Chat/releases/latest`：

| 结果 | 界面 |
|---|---|
| 远端版本 > 当前 | 「发现新版本 vX」+「前往下载」（浏览器打开 release 页） |
| 远端版本 ≤ 当前 | 「已是最新版」 |
| 网络失败 / 限流 / 结构不认识 | 「检查失败」 |

要点：

- **只在用户点的时候发**，不在启动时偷偷请求（会暴露一次匿名调用，也浪费流量）；
- 版本比较是纯函数 `isNewerVersion`：去 `v` 前缀、按 `.` 逐段比数字、缺段按 0
  （`1.1` == `1.1.0`）、预发布后缀截断不参与（`1.1.6-beta.1` 比 `1.1.5` 新、
  但不比 `1.1.6` 新）；
- 用**独立的 OkHttp 客户端**（15s 读超时）：对话那个的 `readTimeout = 0` 是给流式的，
  拿它查版本会一直转圈；
- 未登录的 GitHub API 限 60 次/小时，一次点击一次请求，够用。
