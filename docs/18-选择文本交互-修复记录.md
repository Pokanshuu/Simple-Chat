# 选择文本交互修复

日期：2026-11-17。对应问题：`17-选择文本交互-外部咨询Prompt.md`。

## 原因

Gradle 实际解析出的 Android Compose Foundation 是 `1.12.1`（BOM `2026.09.00`）。核对 Google Maven 发布的对应 sources.jar：

- `commonMain/androidx/compose/foundation/text/selection/SelectionManager.kt` 的 `onClearSelectionRequested` 在 **UP** 阶段排除超过 touch slop 的拖动；没有“普通 DOWN 必定清选区”的行为。
- 同类的 `onFocusChanged` 会在失去焦点时调用 `onRelease()`。
- 应用自己的 `Controls.kt / dismissKeyboardOnTouch()` 在 **Initial / DOWN** 无条件 `clearFocus()`。这是滑动尚未成立、选区就消失的直接原因。列表内测试如果不包含这层外部修饰符，会漏掉问题。
- 原退出手势比较 `positionChange()`（相邻两帧的移动），缓慢滑动时每帧都小于 slop，会被当成轻点。
- “滚动直接清 selectingId”的补丁把症状固定成了一滑就退出。
- 条目级 `remember { SelectionState() }` 单独不能保证离屏恢复；`SelectionContainer` 的 dispose 会清除其 selection。进入选择时切换正文组合位置，还可能重置分页及代码块展开状态。

## 实现

保留 Compose 原生选区，不引入反射、框架内部接口、自绘高亮或只读输入框。

1. `MessageTextSelection` 协调屏幕级选择态；`SelectionState` 继续持有原生范围与手柄。
2. 消息区和顶栏的键盘收起逻辑，在选择态保留焦点。正常输入状态的键盘处理不变。
3. 屏幕及列表在 Initial 阶段旁观，按距 DOWN 的累计位移、时长和指针数量区分轻点；只消费完成轻点的 UP。滚动、长按和原生手柄窗口继续使用自身的事件流。
4. 选择态下统一关闭消息行的点击/长按菜单，退出的那次轻点也不会穿透触发按钮。
5. 用 `LocalPinnableContainer` 只固定选中的条目；退出后释放。保留完整 registrar、Text 节点、分页状态，无须每帧重算字符几何，也不靠重复 `select()` 恢复范围。
6. 用 `movableContentOf` 在进入/退出 SelectionContainer 时移动原正文，保留当前页及代码块的展开状态。
7. 删除滚动退出补丁。原生 Copy、失焦清选区、消息删除或会话切换会同步退出模式；在图片等不可选处无法起选时也退出，避免留下门控。
8. 初始起选仍重放原按下坐标，但长按时长使用设备实际配置，协程取消时发送 CANCEL，避免延迟 UP 遗留到下一页面。
9. 代码语言/行数/展开按钮与分页控件使用 `DisableSelection`；公式源码取消嵌套 SelectionContainer，加入消息的同一选区。Canvas 公式及图片按非文本跳过。
10. 展开的长用户消息使用无间距 Column 承载文本分块，避免 SelectionContainer 将多个直接子节点放在同一个原点，导致文字重叠和复制顺序异常。

## 验证

回归入口：`TextSelectionRegression`，由已有 `DeviceRegression` 的 `selection=true` 参数运行。测试通过真实 Android 输入分发调用生产 MessageList、键盘收起修饰符、原生 SelectionState 和原生复制工具栏；不模拟选择算法。

```text
adb shell am instrument -w -e selection true com.simplechat.app.debug.test/com.simplechat.app.DeviceRegression
```

检查范围包括原按下点起选、慢速累计拖动、惯性滚动、完整离屏后返回且原生锚点不变、另一条回复流式更新、长按跨段落拖选、跨 Markdown/代码/表格复制、其他消息/顶栏/留白点击退出且无点击穿透、用户气泡及非首页分页内容的离屏恢复和再次进入菜单。

最终结果：调试 APK 与测试 APK 构建成功；上述设备回归全部通过，包括展开长用户气泡的分块文本复制顺序。单元测试共 638 项，628 项通过，10 项因缺少外部备份测试文件按既有条件跳过，失败为 0。

本地验证设备为 Pixel 8 Pro 模拟器 / Android 14（API 34）。其他 Android 版本尚未逐一实测；不能据此宣称 Android 8–16 全部通过。流式验证是另一条回复更新时保留已选消息；保持原有“正在生成的消息不开放操作菜单”的行为。

分页的原生全选范围为当前已渲染页；不包含尚未渲染的其他页。未改变整条消息复制入口的范围。
